# 第 6 部分 语言与风格

本部分的规则全部可机检或有明确判据。"读起来别扭"不是判据，能指到具体词、具体句长、具体位置才是。

## 6.1 准确性：让断言可证伪

| 规则 | 判据 | ID |
|---|---|---|
| 强断言给条件 | 含"总是/从不/一定/必然"的句子，须有适用条件或改为限定表述 | LANG-06 |
| 因果与相关分离 | "导致/引起/造成"须有机制说明；只有时间先后时用"同时出现" | LANG-07 |
| 量化带口径 | 数字须带对象、范围、时间窗 | LANG-08 |
| 否定给替代 | "不要用 X"须给"用什么"或"什么条件下可以用" | LANG-09 |

**LANG-06**（MUST｜脚本 L-LANG-06｜阻断）：强断言须给适用条件，或改为限定表述。

**LANG-07**（SHOULD｜自检｜登记）：因果句须附机制。只有时间先后时，改写为"同时出现"。

**LANG-08**（SHOULD｜脚本 L-LANG-08｜登记）：数字须带对象、范围、时间窗。

**LANG-09**（SHOULD｜自检｜登记）：禁令须给替代方案或适用条件。只给禁令的书，读者遇到应用 X 的场景就无路可走。

## 6.2 三种语气必须字面可区分

| 语气 | 标记 | 例 |
|---|---|---|
| **事实** | 无标记，有来源 | "默认上限是 10（官方文档 v8.0）" |
| **推断** | 必须带"推断/推测/未实测"之一 | "推断：瓶颈在序列化阶段（未实测）" |
| **建议** | 必须带条件或理由 | "若写入量大于读取量，把这个参数调低" |

**LANG-03**（MUST｜脚本 L-LANG-03｜阻断）：推断句缺标记即视为把推断伪装成事实。

**LANG-10**（SHOULD｜自检｜登记）：一句同时含两种语气的标记，视为不可判定，拆句。"这说明……"属歧义开头，其后应跟推断标记或来源。

## 6.3 禁用词

四类，命中即改，不设"少量可用"。

| 类别 | 词 | 为什么禁 | 替换 |
|---|---|---|---|
| **空泛强调** | 注意、重要、务必、千万、显然、众所周知、不言而喻 | 无判定标准，只增噪音 | 删，或给具体后果 |
| **主观评价** | 强大、优雅、高效、完美、极致、丰富、灵活、轻松、简单、容易 | 不可验证，常掩盖代价 | 给可测属性或代价 |
| **营销话术** | 一键、开箱即用、一站式、业界领先、最佳实践 | 承诺过度，边界不明 | 写前置条件与适用场景 |
| **填充过渡** | 首先、其次、最后、接下来、值得注意的是 | 靠结构词衔接，说明内容没接上 | 用内容衔接 |

**LANG-01**（MUST｜脚本 L-LANG-01｜阻断）：禁用词零命中，白名单见 `tools/spec_lint.py`。

**白名单只有三类**：定义规则的句子（含"禁止/不得/禁用"）、反例（含"反例/不合格/病句"）、词表本身。词表指标题含"禁用词"的小节。把词写进反例不算命中，把词当强调用就算命中。

## 6.4 十种句法病灶

| 病灶 | 表现 | 改法 |
|---|---|---|
| **名词化堆叠** | "对性能的优化进行了验证" | 还原动词："验证了优化是否提升性能" |
| **被动掩盖施动者** | "该配置被认为是必要的" | 指明谁认为、依据是什么 |
| **长定语套嵌** | 一个名词前挂三个以上修饰 | 拆两句 |
| **逗号串句** | 一句五个逗号无主句 | 断句 |
| **双重否定** | "不是没有问题的" | 直陈 |
| **模糊指代** | "这一点""该方案"指代不清 | 换名词 |
| **同义反复** | "首先第一步" | 删一个 |
| **悬空修饰** | "作为初学者，这个参数很难懂" | 补主语 |
| **中英夹生** | "这个 feature 的 behavior" | 择一语言 |
| **量词错配** | "一个数据" | 改量词 |

**LANG-02**（SHOULD｜自检｜登记）：十种病灶逐条自查，命中即改。脚本只能检其中四种（长句、逗号串、中英夹生、同义反复）。

## 6.5 句长与段落指标

| 指标 | 阈值 | ID |
|---|---|---|
| 单句长度 | ≤60 字（中文字符计） | LANG-05 |
| 段落句数 | ≤6 句 | LANG-11 |
| 段落平均句长 | 20–40 字 | LANG-12 |
| 连续同结构句式 | 不得连续 3 句 | LANG-13 |

**LANG-05**（MUST｜脚本 L-LANG-05｜阻断）：单句不超过 60 字。

**LANG-11**（MUST｜脚本 L-LANG-11｜阻断）：段落不超过 6 句。书稿段落可以比公文短，长段落是读者跳读的起点。

**LANG-12**（SHOULD｜脚本 L-LANG-12｜登记）：段落平均句长落在 20–40 字。低于下限即碎片化。

**LANG-13**（SHOULD｜自检｜登记）：不得连续 3 句使用同一句式结构。

**LANG-05 的反规避**：把长句拆成逗号碎片后，段落均句长会掉到 20 字以下，触发 LANG-12。两条规则互相咬合，单条可绕，组合不可绕。

## 6.6 中英混排、单位、人称

| 规则 | 要求 |
|---|---|
| 中英之间加空格 | `使用 Redis 缓存`，不是 `使用Redis缓存` |
| 专名保留原文 | 首现给中文 + 原文，之后统一一种 |
| 数字用半角 | `3 个`、`10 ms` |
| 单位与数值间加空格 | `12 ms`、`8 GB` |
| 人称 | 用"你"或"读者"，全书统一；不用"我们"替读者承担错误 |
| 时间锚 | 中文无时态，用"截至 2026-10"这类锚点 |

**LANG-14**（SHOULD｜脚本 L-LANG-04｜登记）：中英混排空格由脚本判定。

**LANG-15**（SHOULD｜自检｜登记）：不宜用"我们"把作者与读者绑在一起承担错误（如"我们都会犯这个错"）。改为"常见错误是……"。

## 6.7 标题

| 规则 | 判据 |
|---|---|
| 标题承载信息 | 不看正文，能说出这节解决什么 |
| 不用问句当标题（排错书除外） | 问句标题会让目录失去检索性 |
| 同层句式一致 | 不得一半动词短语、一半名词短语 |
| 不含禁用词 | 与正文同标准（LANG-01） |

**LANG-16**（MUST｜自检｜阻断）：把标题当问题念。念不出问题，说明标题是标签而非内容。

| 标签式 | 内容式 |
|---|---|
| "配置说明" | "把连接池上限从 10 调到 50" |
| "原理" | "为什么扩容后延迟反而升高" |
| "最佳实践"（反例） | "写入密集时该关掉批量提交" |

**LANG-17**（SHOULD｜自检｜登记）：除排错书与章末思考题外，标题不用问句。

**LANG-18**（SHOULD｜自检｜登记）：同一层级的标题句式一致。

## 6.8 风趣的分寸

§0.1 给了原则，这里给可执行细则。**幽默不是风格装饰，是节奏工具**：它出现在长段机制解释之后，给读者一个喘息点，同时把那个反直觉的事实钉住。

### 三个合法用法

| 用法 | 例 | 为什么有效 |
|---|---|---|
| **自嘲** | "我第一次读这段源码时，花了四十分钟才明白它只是把两个变量换了个名字。" | 拉平作者与读者的位置，读者敢承认自己没懂 |
| **荒诞对照** | "这个选项叫 `safe_mode`。开启后它不做任何检查。" | 用事实的反差制造记忆点，不额外编造 |
| **历史的无奈** | "为什么是 1024 而不是 1000？因为四十年前有人图省事，我们至今在还这笔债。" | 把技术决策还原成人做的决策，读者理解得更牢 |

### 四个禁区

| 禁区 | 原因 |
|---|---|
| 嘲讽读者或某类从业者 | 读者一旦觉得被嘲笑，后面写什么都不信了 |
| 拿地域、性别、年龄、职业、身体特征找笑点 | 与技术内容无关，且冒犯代价不对称 |
| 网络热梗、谐音梗 | 半年后过期，书是五年期的产品 |
| 连续两段都在开玩笑 | 密度失控，技术内容被稀释 |

**HUMOR-01**（MUST｜脚本 L-HUMOR-01｜阻断）：不得使用 emoji、感叹号连用、拟声词。技术书的幽默靠事实的反差，不靠标点。

**HUMOR-02**（SHOULD｜自检｜登记）：每章幽默不超过 4 处，不得连续两段出现。

**HUMOR-03**（MUST｜自检｜阻断）：幽默不得替代论证。删掉那句玩笑，若该段论证不成立，说明你在用玩笑掩盖没想清楚的地方。

**HUMOR-04**（MUST｜自检｜阻断）：出错示范中只嘲讽坑，不嘲讽踩坑的人。写"这个配置会静默失败"，不写"新手总在这里翻车"。

## 6.9 图表

| 用途 | 形态 | 不该用 |
|---|---|---|
| 结构关系 | 框图 | 表格（看不出层级） |
| 流程与分支 | 流程图 / 判别树 | 长段文字 |
| 数量对比 | 柱状 / 条形 | 饼图（超 3 项不可读） |
| 趋势 | 折线 | 柱状（连续量） |
| 分布 | 箱线 / 直方 | 均值单点 |
| 状态迁移 | 状态图 | 表格 |

**数据图六要素**（缺一不该出现这张图）：

1. 轴标签 + 单位
2. 样本量或采样窗口
3. 离散度（误差棒 / 分位数 / 区间）
4. 基线（对比对象）
5. 纵轴不从非零截断（除非明示）
6. 颜色不单独承载语义（配形状或标签）

**FMT-01**（MUST｜自检｜阻断）：六要素缺任一项，删图或补全。没有基线的图，读者无法判断大小。

**FMT-02**（MUST｜自检｜阻断）：图必须由图源文本生成（脚本、Mermaid、绘图代码），不用截图。截图无法随数据更新，也无法被检索。

**FMT-03**（MUST｜自检｜阻断）：每张图有一句"读图结论"，写出要读者看到的那一件事。写不出，说明图没有论点。

## 6.10 表格

| 规则 | 要求 |
|---|---|
| 一表一用 | 一张表只回答一个问题 |
| 表头有单位 | 数值列表头写单位 |
| 不用合并单元格表达层级 | 改分组或拆表 |
| 空值有含义 | `—`（不适用）与 `?`（未测）区分 |
| 表内断言同样需来源 | 表格不是免检区 |

**FMT-04**（SHOULD｜脚本 L-FMT-01｜登记）：表格列数一致，表头非空。

## 6.11 引用与出处

**CITE-01**（MUST｜脚本 L-CITE-01｜阻断）：每个外部引用给 `{标题, url, 版本或日期, locator}`。裸链接不算引用。

**CITE-02**（SHOULD｜自检｜登记）：不宜二级引用（"某文章说官方文档写了……"）。追到一手来源，追不到则降级 E2。

**CITE-03**（MUST｜CI｜阻断）：链接可访问且内容与引用描述一致。只查 200 不够——页面存在但已改版，引用内容消失，仍属失效。

**CITE-04**（MUST｜自检｜阻断）：引用版本相关内容必须写明适用版本。读者在 v9 上照 v8 的书操作，是本书最常收到的一类差评。

## 6.12 一致性

| 维度 | 检查 | 方式 |
|---|---|---|
| 术语 | 只用术表正名 | 脚本 |
| 编号 | 图表 / 代码 / 章节编号连续无跳号 | 脚本 |
| 交叉引用 | `§X.Y` 目标存在 | 脚本 |
| 代码与正文 | 正文提到的函数名 / 参数名在代码中存在 | 脚本 |
| 图表与数据 | 正文数字与图一致 | 脚本 |

**FMT-05**（MUST｜脚本 L-XREF-01｜阻断）：交叉引用目标不存在即阻断。长篇里"见 §7.3"指向已删小节，是最常见的失效引用。


## 6.13 时效性

| 做法 | 说明 |
|---|---|
| 版本锚 | 每个版本相关断言写"截至 vX.Y" |
| 隔离区 | 易过期内容集中到"版本差异"小节，便于整节替换 |
| 复审日期 | 易过期小节标 `review_by: 2027-01` |
| 弃用标记 | 旧写法保留但标 `deprecated since vX` |

**TIME-01**（SHOULD｜自检｜登记）：`outline.json` 的 `risk` 所列内容必须有 `review_by`。没有复审日期的时效声明等于没有。
