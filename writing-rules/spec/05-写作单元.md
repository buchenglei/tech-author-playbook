# 第 4 部分 写作单元

这是全书最核心的部分。**一节 = 一个写作单元 = 一句承诺 + 一份 spec + 一次生成 + 一次校验 + 一次冻结。** 不允许"边想边写一整章"。

## 4.1 文件布局

```text
books/<slug>/                 # init_book.py 生成；文件名与 G0–G7 一致
  01_立项卡.json
  02_outline.json             # 结构唯一真源
  03_单元spec.md              # 单元 spec 模板
  04_ledger.csv
  05_state.json
  06_glossary.json
  07_style.kernel.md
  08_读者假设.md
  conflicts.jsonl
  units/
    C03-S2.spec.md            # 写正文之前生成
    C03-S2.md                 # 正文
    C03-S2.check.json         # 校验结果（可由 spec_lint --json 落盘）
  handoff/                    # S7 六文件（sync_handoff.py）
  chapters/                   # assemble_book.py 生成（ch1.typ…）
```

**UNIT-01**（MUST｜脚本 S-UNIT-01｜阻断）：`.spec.md` 必须先于 `.md` 存在。没有 spec 直接写正文，视为未立项的写作，不计入进度。

**为什么用文件而不是"在心里规划"**：你的规划会随上下文丢失，文件不会。spec 是这一节的合同，也是中断后唯一能让你准确续写的东西。

## 4.2 spec 十一项

| # | 字段 | 要求 | 缺了会怎样 |
|---|---|---|---|
| 1 | `id` | 与 `outline.json` 一致 | 无法对齐状态 |
| 2 | `question` | 本节回答的那一个问题 | 写着写着跑题 |
| 3 | `bridge` | 上一节留下了什么 | 变成并列内容 |
| 4 | `layer` | 本节属于现象层、机制层还是代价层 | 三层塌成一块 |
| 5 | `produces` | 本节产出的可见物 | 读者读完没得到东西 |
| 6 | `claims` | 断言清单（§4.3） | 事实与来源倒挂 |
| 7 | `evidence` | 每条断言的来源或"待实测" | 虚构入口 |
| 8 | `concepts_introduced` | 新术语 + 一句定义 | 术语漂移 |
| 9 | `concepts_used` | 依赖的已有术语 | 依赖后置 |
| 10 | `code` | 涉及的文件与行号范围 | 手写代码替换真代码 |
| 11 | `word_budget` | 目标字数与上下限 | 注水或截断 |

**UNIT-02**（MUST｜脚本 S-SPEC-01｜阻断）：十一项缺一不得生成正文。允许某项写"无"，不允许字段缺失。

**UNIT-03**（SHOULD｜自检｜登记）：`layer` 应与 `outline.json` 的 `role` 对齐。本节写的是现象，却在讲机制，说明切分错了。

## 4.3 断言前置：先清点，再写句子

人的默认顺序是"想到什么写什么，写完再核对"。你的默认顺序必须是**先清点断言，再组织语言**。原因：句子一旦生成，你会为它寻找来源；而来源应当先于句子存在。

### 三步

| 步 | 动作 | 产出 |
|---|---|---|
| **① 清点** | 列出本节所有事实断言，一句一条，编号 `A1, A2…` | `claims` |
| **② 定级** | 每条标 `E0/E1/E2/E3`，写来源或"待实测" | `evidence` |
| **③ 降级** | `待实测` 的先跑；跑不了的改写成 E3 句式或删 | 定稿 `claims` |

```text
| #  | 断言                              | 级 | 来源 / 命令              |
|----|-----------------------------------|----|--------------------------|
| A1 | 默认连接池上限是 10                | E1 | 官方文档 v8.0 §Pool      |
| A2 | 并发 50 时 43% 请求等待超过 1 s    | E0 | bench/pool.py，见 E-014  |
| A3 | 容器里这种情况更严重               | E3 | 推断：CPU 配额导致调度延迟 |
```

`A3` 只能写成："在 CPU 配额受限的容器里，等待时间会进一步拉长（推断，未实测）。"

**UNIT-04**（MUST｜自检｜阻断）：正文每段至少对应一条 `claims`，或属于纯结构句（承接、过渡、收束）。存在不对应任何断言的"知识性段落"，说明清单漏了。

**UNIT-05**（MUST｜脚本 L-CLAIM-01｜阻断）：正文每个数字能回溯到 `claims` 与 `ledger.csv`。

**UNIT-06**（MUST｜自检｜阻断）：不得先写句子再补来源。可检迹象：来源描述与句子措辞高度一致，却指向泛泛的文档首页。判据：`locator` 必须细到章节、函数、行号或页码。

## 4.4 六个位置与生成顺序

**六个位置是写前脚手架，不是成文目录。** 它们决定你生成与自检时脑子里有什么，**禁止**以「现象：/机制：/证据：/代价：/误区：/收束」等标签出现在正文小节标题里（LANG-19）。成文应当溶解这条链：读者跟着问题走完「看到现象 → 追问为什么 → 被证据钉住 → 意识到代价 → 避开误区」，但意识不到模板。

| 序 | 位置 | 作用 | 归属层 | 生成次序 | 成文形态 |
|---|---|---|---|---|---|
| 1 | **现象** | 可观察、略带意外的起点 | 现象层 | 4 | 开头的场景/反直觉事实，不标牌 |
| 2 | **机制** | 为什么会这样 | 机制层 | 2 | 推演主干，占篇幅主体 |
| 3 | **证据** | 实测或引用 | 机制层 | 1 | 行文中的钉子（E-xxx），不单开一节 |
| 4 | **代价** | 何时失效、怎么选 | 代价层 | 3 | 推演尽头的边界与账单 |
| 5 | **误区** | 常见错解 | 代价层 | 5 | 融入判断句，或「会判断错的地方」式修辞 |
| 6 | **收束** | 留给下一节什么 | — | 6 | 末段留钩，不写「本章小结」 |

**生成顺序：证据 → 机制 → 代价 → 现象 → 误区 → 收束。** 写完后做「去壳检查」：把表格与编号抽掉，是否仍是可跟着走的推演。

**UNIT-07**（MUST｜自检｜阻断）：`现象` 在第四位写，不得先写开头。理由：开头只能承诺你已能兑现的东西。先写开头，你会为了圆开头而扭曲证据——这是最常见的失真路径。

**UNIT-08**（MUST｜自检｜阻断）：`代价` 不得为空。每节至少写一条"本节结论在什么条件下失效"。找不到代价，说明结论被夸大了。

**UNIT-21**（MUST｜脚本 L-FORM-01｜阻断）：正文小节标题禁止使用「现象 / 机制 / 证据 / 代价 / 误区 / 收束 / 小结」加冒号的挂牌式标签（附录、工具书条目、规范自身可豁免）。标题应是问题、发现或动作。

**UNIT-23**（MUST｜脚本 L-VOL-01｜阻断）：冻结前正文字符数（中文计）须 ≥ `00_大纲合同.json` 的 `section.words_absolute_min` 与 `words_min_ratio × 该节 words 预算` 二者较大值。低于则视为梗概/提纲，不得 frozen。**写正文严禁「最少 token」策略**（质量与大纲深度优先）。

**UNIT-24**（MUST｜自检｜阻断）：若用户写作大纲含明确写法（如每章固定小节、必须命令+预期输出），须在阶段 1《大纲×规范融合评估》列出并与本规范对照，交人裁决后再写；不得静默按 playbook 忽略大纲。

**UNIT-22**（SHOULD｜脚本 L-FORM-02｜登记）：每节正文表格建议不超过 2 张。附录、速查、工具书条目豁免。表格只用于对照或对账；自由区可偏离，须在滚动评估「偏离记录」写一句理由。

**UNIT-09**（SHOULD｜自检｜登记）：`机制` 在正文中的篇幅占比不低于三成，不高于七成。低于三成，机制讲不清；高于七成，读者会被细节淹没。判据：按字数统计。

**UNIT-10**（SHOULD｜脚本 L-SYM-01｜登记）：禁止对称填充。连续三节结构与字数高度雷同（各位置字数比例接近、句式模板重复），触发结构审查。内容决定结构，雷同说明在套模板。

## 4.5 段落级规则

| 规则 | 判据 | 处置 |
|---|---|---|
| 一段一义 | 每段有且仅有一个论点 | 拆段 |
| 主题句在前 | 首句能独立表达该段主张 | 调语序 |
| 段内推进 | 每句比上一句多给一点（条件、数据、反例） | 删原地打转的句子 |
| 禁空洞过渡 | "首先/其次/最后""接下来我们来看" | 删，靠内容衔接 |
| 禁复述式收尾 | 段末把段首再说一遍 | 删 |
| 术语一致 | 同一概念只用 `glossary.json` 正名 | 全局替换 |


**UNIT-11**（SHOULD｜脚本 L-LANG-01/02｜登记）：句长、段落、过渡词受第 6 部分约束，由脚本判定。

## 4.6 术语锚：改词是全局操作

**UNIT-12**（MUST｜自检｜阻断）：新术语首次出现即写入 `glossary.json`：`term`、`def`（一句，≤40 字）、`first_seen`、`aliases_forbidden`。

**UNIT-13**（MUST｜自检｜阻断）：改术语要三步同做：改术表 → 全局替换正文 → 在 `state.json` 记 `term_migrations`。只改一处即产生漂移。

| 漂移表现 | 后果 |
|---|---|
| 同一概念三种叫法 | 读者以为是三样东西 |
| 定义在第 2 章与第 7 章不一致 | 长篇最致命的错误，且最难发现 |
| 别名混用（"连接池/连接缓冲区"） | 检索失效，索引对不上 |

## 4.7 代码与实验

代码是失真风险最高的部分：你会生成"看起来对"的代码。

### 五条硬约定

| # | 约定 | 判定 |
|---|---|---|
| 1 | **单一真源**：正文代码从仓库抽取，不手写 | 代码块带 `<!-- src: path:start-end -->`，抽取脚本可复现 |
| 2 | **必须执行**：每个代码块至少跑过一次，退出码 0 | CI 日志 |
| 3 | **输出照录**：示例输出来自实际运行，不修饰 | 输出块带 `<!-- out: E-xxx -->`，对应台账 |
| 4 | **完整可运行**：读者复制即跑，不省关键行 | 用 `...` 省略时，必须给完整版位置 |
| 5 | **版本锚定**：涉版本差异的，标适用版本与回落写法 | 版本号取自 E1 记录 |

**UNIT-14**（MUST｜脚本 S-CODE-01｜阻断）：代码块须可溯源——`src:`/`path:` 标注，或同节台账 `E-xxx` 覆盖该代码/命令（宪法 C-05）。三者皆无则视为手写代码，不得发布。

**UNIT-15**（MUST｜自检｜阻断）：示例输出不得整理。报错原文、时间戳、地址保持原样；敏感信息用 `<REDACTED>` 标记并说明替换规则。

**UNIT-16**（MUST｜自检｜阻断）：命令必须可直接复制执行。不得出现 `$ ` 前缀混进可复制区、不得用中文标点当路径分隔符、不得写"在你的项目里改一下"这类无法执行的指令。

### 命令块格式

```bash
# 目的：验证连接池上限是否生效
# 前置：已执行 03-setup.sh
docker exec app env | grep POOL_SIZE
```

**UNIT-17**（SHOULD｜自检｜登记）：每条命令前给一行目的，读者才知道该期待什么。这不是注释，是判据。

## 4.8 五类禁止编造

| 类型 | 你会怎么编 | 无来源时怎么办 |
|---|---|---|
| **API 与参数** | 补一个"应该有"的方法名 | 删该调用，改为描述行为 + 官方文档链接 |
| **运行结果** | 编一段"预期输出" | 写"运行后应看到包含 X 的行"，不写具体数字 |
| **因果解释** | 把相关当因果 | 改为"与该现象同时出现"，并标未验证因果 |
| **版本行为** | 凭印象说"从 v4 起支持" | 查 changelog；查不到则删版本断言 |
| **生态评价** | "社区普遍认为……" | 删，或改为具名来源的观点 |

**UNIT-18**（MUST｜自检｜阻断）：降级不是免责。降级后的句子必须让读者看出不确定性，不得用肯定语气包装弱证据。

**降级句式库**（只用这五种，不自创模糊说法）：

| 句式 | 适用 |
|---|---|
| "在本文的测试环境（见 §X）中，观察到……" | 单一环境实测 |
| "官方文档称……（版本 X，§Y）" | 引用未复现 |
| "推断：……（未实测）" | E3 |
| "若你的环境满足……，则预期……" | 条件性结论 |
| "本节未验证这一点" | 明确留白 |

## 4.9 单元完成定义与冻结

**DoD 两档**：写作中快检三项（只答 question / 代价非空 / 数字挂账）；**冻结前八项全过**：



| # | 项 | 判定 |
|---|---|---|
| 1 | 只回答 `question` | 自检：每段能对应 question 的一部分 |
| 2 | `produces` 已交付 | 产物在正文或代码中可见 |
| 3 | 六个位置齐全且未挂牌，`代价` 非空 | 脚本 + 自检 |
| 4 | 三层之间有承接句与转折句 | 自检（ENG-07/08） |
| 5 | 数字全部可回溯台账 | 脚本 |
| 5b | 实写字数达大纲合同下限（UNIT-23） | 脚本 L-VOL-01 |
| 6 | 代码块带 `src` 且执行过 | 脚本 |
| 7 | 语言指标通过 | 脚本 |
| 8 | 节尾留钩，指向下一节 | 自检 |

**UNIT-19**（MUST｜自检｜阻断）：DoD 全过、`quality_gate.py` 无 P0，且有独立审阅记录后，由审阅者/人把 `outline.json` 中该节 `status` 置为 `frozen`；Agent 只能置 `checking`/`candidate`。未冻结不得进入下一节。

**UNIT-20**（MUST｜自检｜阻断）：冻结后要改，须新建 `revision` 记录，写明触发原因：校验失败、评审意见或事实变更。并重跑该节全部检查。禁止静默改写。

## 4.10 门禁 G3（样章）

**批量写作前，先完成一节样章并通过 G3。** 样章暴露的问题会重复几百次；改一节比改一百节便宜。

| 检查 | 方式 | 通过条件 |
|---|---|---|
| spec 十一项齐全 | 脚本 | 零缺失 |
| 断言清单与正文对应 | 自检 | 无孤立知识段落 |
| 六个位置齐全（不挂牌） | 脚本 | 零缺失、零挂牌标题 |
| 表格密度 | 脚本 | 每节 ≤2 张 |
| 三层有承接与转折 | 自检 | 每层交界有转折句 |
| 代码可执行 | CI | 退出码 0 |
| 语言指标 | 脚本 | 零 P0 |
| 节尾钩子成立 | 自检 | 下一节 `bridge` 接得上 |
