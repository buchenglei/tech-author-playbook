# 第 9 部分 交接

## 9.1 四个角色

同一模型可分饰，但**职责必须分开**，否则自评会污染验证。

| 角色 | 产出 | 禁止 |
|---|---|---|
| **规划者** | 立项卡、`outline.json`、`style.kernel.md` | 写正文 |
| **写作者** | 单元 spec + 正文 | 改大纲、改自己的校验结论 |
| **校验者** | `check.json`、问题清单 | 修正文 |
| **编辑者** | 语言修订 | 改事实（须回写作者） |

**TEAM-01**（MUST｜自检｜阻断）：同一单元的作者与校验者不得是同一角色实例。环境只允许一个 Agent 时，校验由脚本 + 人类抽检承担，并在报告声明"未做独立校验"。

## 9.2 交接物是文件，不是对话

| 交接 | 交出 | 接收方据此能做什么 |
|---|---|---|
| 规划 → 写作 | `outline.json` + 该节 spec | 直接开写，无需追问 |
| 写作 → 校验 | 正文 + `claims` + 台账行 | 逐条核 |
| 校验 → 写作 | `check.json`（规则ID + 位置 + 证据） | 按 ID 定位修 |
| 写作 → 人类 | 交接包（§9.4） | 做 L2 判定 |

**TEAM-02**（MUST｜自检｜阻断）：交接不得依赖对话上下文。接收方只读文件就能继续，否则接口不合格。

## 9.3 人类只做三件事

| # | 事 | 为什么你不能做 | 输入 | 输出 |
|---|---|---|---|---|
| 1 | **读者任务测试** | 你需要真实读者的卡点数据 | 交接包 + 干净环境 | 卡点表 |
| 2 | **领域正确性判断** | 你的判断来自同一份材料 | 复现清单 | 对 / 错 / 存疑 |
| 3 | **目标与取舍拍板** | 涉及商业与伦理判断 | 二选一卡片 | 选择 |

**TEAM-03**（SHOULD｜自检｜登记）：不宜为人类制造第四类工作（"帮我看看写得顺不顺"这类无判据请求）。每个请求应带判据与产出格式，否则人类会退化成你的校对工具，而校对质量不稳定。

## 9.4 交接包协议

一个目录，六个文件，缺一不得交付。

| 文件 | 内容 | 人类用它回答什么 |
|---|---|---|
| `00_README.md` | 这是什么书、给谁、怎么读、哪些未验证 | 我该从哪看 |
| `01_outline.json` | 结构 | 结构合理吗 |
| `02_glossary.json` | 术语 | 说法统一吗 |
| `03_ledger.csv` | 断言与来源 | 这些话有依据吗 |
| `04_check.json` | 各级校验结果（含未通过项） | 哪些还没过 |
| `05_unverified.md` | 未验证项 + 原因 + 影响 | 哪里可能出错 |

**TEAM-04**（MUST｜自检｜阻断）：`05_unverified.md` 不得为空。**一份声称全部验证过的技术书稿，几乎一定有一项在说谎。** 若确实全部实测，写明实测环境与覆盖范围。

## 9.5 反馈入库格式

反馈不能直接改文，先转成可执行项。

| 反馈原文 | 转成 | 入库位置 |
|---|---|---|
| "这段看不懂" | 卡点：位置 + 类型（缺前置 / 句子太长 / 指代不明） | `issues.jsonl` |
| "这个结论不对" | 事实异议：断言 ID + 反例 | `ledger.csv` 新增一行 |
| "太啰嗦" | 规则命中：LANG-11 或复述式收尾 | `check.json` |
| "应该加一节讲 X" | 范围变更：进 `scope_in` 或拒绝并说明 | `conflicts.jsonl` |

**TEAM-05**（SHOULD｜自检｜登记）：未转成上述格式的反馈不宜直接执行。**"看不懂"改成"加一段解释"是最常见的错误修法**，它会掩盖真正的根因（通常是前置概念缺失或结构错位）。

## 9.6 冲突仲裁

| 冲突 | 仲裁依据 |
|---|---|
| 两 Agent 术语不一致 | 以术表为准，后者改 |
| 校验者说错、写作者说没错 | 看证据，不看理由；无法判定则升级人类 |
| 人类意见与 MUST 冲突 | 规范优先，记录 `conflicts.jsonl`，并说明代价 |
| 人类意见与 SHOULD 冲突 | 人类优先，登记豁免 |

**TEAM-06**（SHOULD｜自检｜登记）：仲裁结果应写文件。口头达成的共识，在下一个会话里不存在。

## 9.7 不可委托清单

以下五项，无论怎么要求，都不得留给"以后再验证"：

| 事项 | 原因 |
|---|---|
| 代码可运行 | 跑不起来的代码让整章失效 |
| 数字有来源 | 编造一次，全书可信度归零 |
| 引用可追溯 | 假引用是第一眼能被发现的错误 |
| 未验证项声明 | 剥夺读者的判断依据 |
| 术语一致 | 长篇的头号可读性杀手 |

**TEAM-07**（MUST｜自检｜阻断）：五项任一未完成，交付状态写 `draft`，不得写 `ready`。
