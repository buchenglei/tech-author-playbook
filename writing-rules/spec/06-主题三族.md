# 第 5 部分 主题三族

同一套实战要求套所有书，会逼出两种坏结果：工具书里编实验，概念书里没法执行。所以先分族，再分别给要求。

## 5.1 三族判定

| 族 | 主题特征 | 判据 | 书中该怎么"实" |
|---|---|---|---|
| **A 可测量** | 性能、容量、并发、成本 | 能给出可复现的数字 | 基准 + 基线 + 归因 |
| **B 工具/语言** | 框架、命令、API、配置 | 有明确的任务链与错误路径 | 任务链 + 故障注入 |
| **C 概念/设计** | 架构、协议原理、方法论 | 主要靠判断而非测量 | 反例 + 判读 + 最小实现 |

**DEM-01**（MUST｜自检｜阻断）：`outline.json` 的 `book.family` 必须声明。混族按章标注，不得全书只用一族。

## 5.2 A 族：基线、测量、归因

| 项 | 要求 |
|---|---|
| **项目 0** | 写任何实验代码前，先建可复现基线：环境、负载、指标、采样方式 |
| **环境四要素** | 版本 + 平台 + 负载 + 采样窗口，缺一不可 |
| **预测先行** | 跑之前先写预测，跑完对比 |
| **归因链** | 现象 → 假设 → 排除 → 结论，每步给证据 |
| **离散度** | 报 P50/P99 或均值±标准差，不只报均值 |

**DEM-02**（MUST｜自检｜阻断）：量化断言必须带四要素。缺一项即降级为"在本文环境中观察到"。

**DEM-03**（MUST｜自检｜阻断）：基准必须给基线。没有基线的数字无法解读——快是相对什么快？

**DEM-04**（MUST｜自检｜阻断）：不得跨环境比较。你机器上的数字不能与官方博客的数字并列表。

**DEM-05**（MUST｜自检｜阻断）：预测与实测不一致时，必须写出不一致的原因。删掉预测、只留结果，等于伪造了推理过程。

## 5.3 B 族：任务链与故障注入

| 项 | 要求 |
|---|---|
| **环境基线** | 版本 + 一条验证命令 + 预期输出（真实执行） |
| **任务链** | 3–6 个递进任务，每个有可验证产物 |
| **故障注入** | 每章至少主动制造 1 个错误，给报错原文与定位过程 |
| **判别树** | 相似错误给分叉判据，不只给"正确做法" |

**DEM-06**（MUST｜自检｜阻断）：故障注入必须是真跑出来的错误，不得手写报错文本。判据：报错内容能在 CI 日志或终端记录里找到。

**这是 B 族最常被跳过的一项，也是书籍价值最集中的地方。** 读者卡住时需要的是判别方法，不是正确路径。

## 5.4 C 族：反例、判读、最小实现

| 项 | 要求 |
|---|---|
| **反例优先** | 先给一个会出问题的设计，再给修正 |
| **判读练习** | 给现象（日志、时序图、指标曲线），问"发生了什么" |
| **最小实现** | 30–80 行可运行的简化版，能演示核心机制 |
| **取舍表** | 至少两方案对比，给放弃理由 |

**DEM-07**（MUST｜自检｜阻断）：最小实现必须可运行并能复现核心现象。跑不起来的伪代码不算最小实现，只能算示意。

**DEM-08**（MUST｜自检｜阻断）：取舍表必须写"为什么不选另一个"。只写优点的对比表等于没有对比。

## 5.5 等价物对照

A 族的每条要求，在 B/C 族都有等价物。**删掉量化要求而不给替代，实战会退化成步骤罗列。**

| A 族要求 | B 族等价物 | C 族等价物 |
|---|---|---|
| 基线测量 | 环境基线 + 验证命令输出 | 前置条件清单 + 反例现象 |
| 环境四要素 | 版本 + 平台 + 依赖版本 | 假设条件 + 适用边界 |
| 预期值区间 | 预期输出（真实） | 预期判断结论 |
| 归因链 | 报错 → 假设 → 排除 → 根因 | 反例 → 失效机制 → 修正 |
| 离散度 | 多环境/多版本差异说明 | 反例的多种触发方式 |
| 跨环境比较禁令 | 跨版本行为差异须分别验证 | 跨场景结论须限定条件 |

**DEM-09**（MUST｜自检｜阻断）：B/C 族**不得为凑"量化"而编造数字**。没有实测就写可观察结果。编造一次，全书可信度归零。

## 5.6 数字纪律

| 规则 | 内容 |
|---|---|
| 来源 | 每个数字有 `E-xxx` |
| 精度 | 不写与采样不匹配的位数（`1.234 s` 需毫秒级采样） |
| 单位 | 必写；时间给单位与量级（`12 ms`，不写 `12`） |
| 舍入 | 同表内一致 |
| 修饰 | 不得用"大约""接近""几乎"修饰未测数字 |
| 外推 | 不得从单点数据外推趋势 |

**DEM-10**（MUST｜脚本 L-CLAIM-01｜阻断）：违反任一条，该段不得发布。

## 5.7 承诺—章节映射

设计阶段必做，两个方向都查：

| 方向 | 查什么 | 失败含义 |
|---|---|---|
| `scope_in` → 章节 | 每个承诺点有对应章节 | 承诺未兑现 |
| 章节 → `scope_in` | 每章对应某个承诺点 | 写了无关内容 |

**DEM-11**（MUST｜自检｜阻断）：映射表不得有空行。空行必须有书面理由，写在表下方。

## 5.8 门禁 G4

| 检查 | 方式 | 通过条件 |
|---|---|---|
| 映射表无未解释空行 | 自检 | 零 |
| 环境基线真实执行 | CI | 有日志 |
| 故障注入真实 | CI | 有报错原文 |
| 数字全部可回溯 | 脚本 | 零未登记 |
| 族别与要求匹配 | 自检 | 逐条对照 §5.5 |
