# 附录 D 故障处置

按症状查，不按原因查——你无法先知道原因。

| 症状 | 可能根因 | 处置 |
|---|---|---|
| 一节写不到预算一半 | 内容不足 | 回 `claims` 清点：断言少于 8 条，说明该节应并入他节 |
| 一节超预算一倍 | 结构未定 | 按 §3.4 拆节，不删内容 |
| 写着写着发现前面错了 | 断言未前置 | 回滚该单元，重做 §4.3 三步 |
| 连续几节结构雷同 | 套模板 | 触发 UNIT-10，按内容重排 |
| 语言检查反复不过 | 句式习惯 | 换修法；三次不过转 BLOCK（§7.3） |
| 术语改了却到处不一致 | 单点修改 | 按 UNIT-13 三步重做 |
| 代码块跑不过 | 环境或版本 | 先固定版本，再改代码，最后改正文 |
| 引用打不开 | 未验证 | 查替代源；无替代则降级 E2 |
| 审校说"读不下去" | 结构或句长 | 先查段落句数，再查三层是否有转折 |
| 读者反馈"讲了半天不知道要说什么" | 现象层缺失 | 该节没有可观察的起点，补一个具体现象 |
| 读者反馈"太干" | 机制层过长 | 加一处自嘲或荒诞对照，但不得超过密度上限 |
| 不知道该写什么了 | 大纲粒度过粗 | 用 §3.4"标题当问句"逐节检验 |
