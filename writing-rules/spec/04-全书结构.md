# 第 3 部分 全书结构

章写对了不等于成书。缺装配时，每章都合格，整本仍是合集。对 Agent 还有个额外风险：**你倾向生成对称结构**——每章等长、每节同构。而结构应由内容决定。

## 3.1 七种书籍类型

先定类型，再定骨架。类型决定默认节奏、实战形态、验收动作。

| 类型 | 读者意图 | 骨架 | 验收动作 |
|---|---|---|---|
| **原理书** | 搞懂一个系统怎么运转 | 分卷；每章一个机制群；层层深入 | 能回答章末判读题 |
| **实战书** | 跟着做出一个完整东西 | 分阶段，每阶段有可运行产物 | 跟做完成，产物可跑 |
| **案例书** | 看真实问题怎么解 | 场景→约束→方案→复盘 | 能说出方案适用边界 |
| **排错书** | 定位当前故障 | 症状→判别树→根因→修法 | 给症状能走到正确分支 |
| **工具书** | 查一个具体用法 | 条目化，字段统一 | 30 秒内查到 |
| **演进书** | 理解设计为什么变成今天这样 | 按时间或问题推进，每步给约束 | 能说出每次改变解决了什么 |
| **通识书** | 给跨界读者建立认知 | 从熟悉事物切入，逐层抽象 | 能向他人解释核心机制 |

**STR-01**（MUST｜脚本 S-TYPE-01｜阻断）：类型取自上表七项之一。混型须在 `outline.json` 标主型与从属部分，或拆成两本。

**STR-02**（MUST｜自检｜阻断）：一本书只有一个主型。原理书里可以有实战章节，但不能一半原理一半实战——读者会不知道该用哪种读法。

## 3.2 三层骨架：卷、章、节

| 层 | 承担什么 | 判据 |
|---|---|---|
| **卷** | 一个问题域 | 能用一句说清"这一卷解决哪类问题" |
| **章** | 一个机制群，有独立产出 | 读完能完成一件可验证的事 |
| **节** | 剥开的一层 | 标题念出来是一个问题，不是一个标签 |

**节的三种职能**（对应 §0.1 三层剥法）：现象节、机制节、代价节。三者不必各占一节，但一章之内三种职能必须齐备。

**STR-03**（MUST｜自检｜阻断）：每章必须能标出哪一节承担现象、哪一节承担机制、哪一节承担代价。缺任一种，该章是资料堆，不是论述。

## 3.3 `outline.json`：结构的唯一真源

正文之外先有结构文件。字段固定，脚本可校验。

```json
{
  "book": {"title": "", "type": "原理书", "claim": "", "target_words": 0, "family": "A"},
  "volumes": [
    {"id": "V1", "title": "", "purpose": "", "chapters": ["C01", "C02"]}
  ],
  "chapters": [
    {
      "id": "C03", "title": "",
      "purpose": "读者读完能完成的一件可验证的事",
      "produces": "本章产出的可见物",
      "role": {"phenomenon": "C03-S1", "mechanism": "C03-S2", "cost": "C03-S3"},
      "requires": ["C01"],
      "words": 0,
      "sections": [
        {"id": "C03-S2", "title": "", "question": "标题念出来的那一句",
         "produces": "", "bridge": "上一节留下了什么",
         "concepts": [], "deps": ["C03-S1"], "words": 0, "status": "planned"}
      ]
    }
  ],
  "paths": [{"name": "线性通读", "order": ["C01", "C02", "C03"]}],
  "concepts": [{"term": "", "first": "C02-S3", "used_in": ["C04-S1"]}]
}
```

| 字段 | 为什么必须有 |
|---|---|
| `purpose` | 没有独立产出的章，是插进来的 |
| `produces` | 产物是章与章的接口，缺了无法递进 |
| `role` | 强制检查三种职能是否齐备（STR-03） |
| `question` | 标题能否成为问句，是粒度判据 |
| `deps` | 支持跳读与拓扑排序 |
| `status` | 与 `state.json` 对齐，避免重复写 |

**STR-04**（MUST｜脚本 S-OUT-01｜阻断）：`outline.json` 通过 schema 校验，`deps` 构成有向无环图。

**STR-05**（MUST｜脚本 S-OUT-02｜阻断）：`deps` 指向的节必须排在前面。有环即结构错误，不得用"见后文"绕过。

**STR-06**（MUST｜脚本 S-OUT-03｜阻断）：每节 `produces` 与 `bridge` 非空。写不出产物，说明这节是背景铺陈，应并入相邻节。

## 3.4 粒度与递进

两个要求：**切分偏细**，**连接要紧**。

### 粒度：宁可细，不要粗

| 层级 | 标准 | 判断方法 |
|---|---|---|
| 章 | 解决一个完整问题，有独立产出 | 读完能完成一件可验证的事 |
| 节 | 回答一个能被独立提出的问题 | 把标题当问题念；念出两个问句就拆 |

**该拆的五个信号**：

| 信号 | 说明 |
|---|---|
| 一节里有两个决策规则 | 两组判断，各需独立依据 |
| 一节里有两个核心命题 | 实为两个主题 |
| 标题要用"与""、"连接两个能力 | 读者预期这是两节 |
| 一节中途要"换个角度再看" | 视角切换处就是切分点 |
| 一节超过一次能读完的长度 | 见 §3.6 |

**不该拆的三种情况**（拆了更差）：

- 拆出的节不足半页，且无独立产出
- 两节共用同一现象或同一示例，拆开要重复铺垫
- 拆完需要三处以上"见上节"才能读懂

**为什么偏细**：粗的章节能细读，细的章节能跳过。你无法预测读者需要哪一段。把一章写成三节，读者能取三样；写成一节，读者只能全要或全不要。

### 递进：每节接住上一节留下的问题

递进不是"内容变深了"，是**上一节明确留下了什么，这一节接着解决**。

| 方式 | 形式 | 例 |
|---|---|---|
| **加约束** | 上节方案在更严条件下如何 | "单机够用。加网络分区后，同样代码会静默重复扣款" |
| **换条件** | 方案不变，改一个前提 | "内存从 8 G 降到 512 M，刚才的结论全部反转" |
| **引入新失败模式** | 补上未覆盖的失效路径 | "上节假设请求有序。乱序时重试会放大故障" |
| **提高规模** | 数量级上去后的行为变化 | "一万条全量重算没问题。一百万条时它成了主要开销" |
| **追问代价** | 上节结论成立，但代价在哪 | "这个方案确实快，代价是每次写入都要等两次落盘" |

**四种反模式**：

| 反模式 | 表现 | 后果 |
|---|---|---|
| **并列式** | A、B、C 各一章，彼此无关 | 记住三个孤立点，不会组合 |
| **跳跃式** | 第 3 章讲 A，第 5 章直接用 A 的进阶，无过渡 | 卡在第 5 章开头 |
| **重复式** | 两章讲同一件事的不同侧面，不说区别 | 不知道为什么读第二遍 |
| **摊平式** | 每章都从零讲一个独立主题 | 无主线，读完像合集 |

**STR-07**（MUST｜自检｜阻断）：`outline.json` 中每节必须有 `bridge`，一句话说明"上一节留下了什么"。写不出即该节是并列插进来的。

**STR-08**（MUST｜脚本 S-OUT-04｜阻断）：每章至少有一处"上一层的解释不够用"的转折节。做法：检查该章 `role.cost` 存在，且其 `bridge` 含反问或未解问题。缺转折的章是平铺，不是剥开。

### 环环相扣：产物继承

前一节的产物是后一节的输入。产物可以是代码状态、一个结论、一条判据、一套已建立的基线。

```text
节首承接：上一节把延迟从 40 ms 降到 12 ms，代价是内存涨了三倍。
节尾留钩：内存换延迟在当前负载下划算。负载再涨一倍，这笔账会反过来。
```

**两条检验**：

| 检验 | 做法 | 判读 |
|---|---|---|
| **抽章测试** | 抽掉一章，看后面有几章 `deps` 指向它 | 0 → 可删或并入；1–2 → 正常；多数 → 核心章，应前移 |
| **跳读测试** | 跳过上一节，本节还读得懂吗 | 懂 → 两节可能并列，合并或声明独立 |

**STR-09**（SHOULD｜脚本 S-OUT-05｜登记）：`deps` 入度为 0 的节超过总数三成时，提示"并列式"风险。理由记入 `state.json`。

## 3.5 三条阅读路径

**STR-10**（SHOULD｜自检｜登记）：长篇（五章以上）应给 2–3 条路径，每条是 `outline.json` 中的有序 ID。

| 路径 | 服务谁 | 要求 |
|---|---|---|
| **线性** | 从零学 | 拓扑序，无跳读 |
| **任务** | 带着问题来 | 直达目标节，前置只列必需 |
| **参考** | 查具体项 | 按功能索引，不按学习顺序 |

路径必须可执行：按列表走，不遇到未定义术语。判据：路径内每个 `deps` 都在更早位置或起点清单里。

## 3.6 篇幅预算

**STR-11**（SHOULD｜自检｜登记）：开写前给每章字数预算，总和对齐 `target_words`。

| 层级 | 参考区间 | 约束来源 |
|---|---|---|
| 节 | 2500–5000 字 | 三层剥法要装现象、机制、代价，且机制占一半 |
| 章 | 3–6 节 | 超过考虑分卷 |
| 卷 | 3–6 章 | 超过考虑拆册 |
| 全书 | 12–25 万字 | 技术书读者的耐心上限 |

**单章超预算 20% 时三选一**：砍范围、拆章、上调全书预算并说明代价。不得默认超。

**STR-12**（SHOULD｜自检｜登记）：区间是参考值。某节 1800 字讲透了，不补写。**字数不足不等于质量不足，字数超标通常等于结构未定。**

## 3.7 目录陌生化测试

人类版目录测试是找人只看目录猜内容。你没有读者，必须清楚替代手段的效力差，**不得把弱替代说成验证**。

| 手段 | 做法 | 效力 | 能发现 | 不能发现 |
|---|---|---|---|---|
| **他人试读** | 只给纯目录，问"想解决 X 翻哪章" | 强 | 标题信息量、切分重叠 | 正文可读性 |
| **自我陌生化** | 清空上下文，只读目录，逐章写"读者会预期什么" | 中 | 标题歧义、章间重叠 | 真实困惑 |
| **术语反查** | 只读目录，查术语是否都在术表 | 弱 | 未定义术语 | 结构与逻辑 |

**STR-13**（MUST｜自检｜阻断）：目录测试至少做到自我陌生化：只读目录，为每章写一句"读者会预期什么"，与 `purpose` 对比。不一致即改标题或切分。

**STR-14**（MUST｜自检｜阻断）：未做他人试读，不得写"目录测试通过"。只能写"仅完成自我陌生化，未做读者验证"，并记入交接包。

## 3.8 门禁 G2

| 检查 | 方式 | 通过条件 |
|---|---|---|
| schema + 无环 | 脚本 | 零错误 |
| `produces` / `bridge` 齐全 | 脚本 | 零空 |
| 每章三种职能齐备 | 脚本 | `role` 三项非空 |
| 路径可执行 | 脚本 | 路径内依赖前置 |
| 陌生化测试完成 | 自检 | 每章有预期句且与 `purpose` 一致 |
| 粒度检查 | 自检 | 无"两个问句"的节 |
