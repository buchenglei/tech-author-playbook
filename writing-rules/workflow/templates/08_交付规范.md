# 交付物规范（tar.gz）

> 人工交付以 **`.tar.gz` 压缩包**为准。包内必须干净、可离线改稿、可从源码重新编出 PDF。

## 1. 必含内容

| 路径（包内） | 说明 |
| --- | --- |
| `README.md` | **开源项目级 README**：书籍简介与承诺、读者对象、目录、快速开始、结构、从源码到产物、贡献/反馈、License |
| `book.pdf` | 最终（或当前）编译产物，供先读 |
| `typst/` | **完整可编译工程**：`main.typ`、`config.toml`、`chapters/*.typ`、`src/`（引擎快照）、`typst.toml` |
| `manuscript/` | 写作工程：`01_立项卡`…`08_读者假设`、`units/`（含 spec）、`02_outline`、台账、术表 |
| `handoff/` | 交接包六文件 |
| `workflow/` | 读者/编辑报告、改进方案、写作宪法、滚动评估、阶段状态（**不含** `archive/`） |
| `MANIFEST.txt` | 文件清单 + `delivery_status`（draft/ready）+ 版本/日期 + 编译命令 |
| `LICENSE` | 开源许可证（默认 MIT，与仓库一致） |
| `FONTS.md` 或 `typst/FONTS.md` | 字体依赖说明 |

> **工具布局**：`quality_gate.py` / `validate_quality.py` 同时接受两种书根；`run_gates` 的 G0–G7 仍以扁平书根为准。
> ①扁平（`units/`+`workflow/`+`02_outline.json` 同级，如 `books/*`）；
> ②交付包（`manuscript/`+`workflow/`+`handoff/`，如本规范）。
> 对交付包根目录直接跑工具即可，无需再手工拼路径。
> 报告文件名兼容 `01_读者报告.md` 与 `01_读者报告-第1章.md`（WORKFLOW §7）。

**建议另含（缺省则须在 README 声明）**

- `outstanding.md`：未验证项与待人工确认项（可与 `handoff/05_unverified.md` 同文）
- `changelog.md`：本书修订记录
- `tools/`：本项目写作期自造/修补过的脚本（如实验复现脚本、`expected-failures.txt` 类反例清单），并回流本仓库（反哺）

**随书工程（台账用 `repo:` 引用时为必含）**

- 台账 `url=repo:xxx` 与正文 `src:` 锚点指向的随书工程（`code/` 或约定目录）**必须随包交付**，否则读者无法编译/重跑——`quality_gate` EVD-17 会对悬空的 `repo:` 引用报 P0（可复核性断链）。

**交付状态与命名（硬约束）**

- `MANIFEST.txt` 与 `README.md` 首部必须标 `delivery_status: draft|ready`；`human_confirmations.final` 未签字一律 `draft`。
- 文件名含「终版/final/ready」而状态为 draft 时，`package_book` 直接拒绝（`--force-name` 显式承担）。
- README 必须是**本书**的 README（简介/承诺/读者/目录/License）；把 playbook 仓库 README 或模板原文交付即为不合格。

## 2. 明确排除（打包前清理）

- `dist/` 内日志：`*.log`、`*.err`、`smoke.pdf`
- `workflow/archive/`、`workflow/memory/`（过程垃圾；仅保留 `CURRENT.md` 可选）
- `.DS_Store`、`__pycache__`、`.venv`、编辑器目录
- `draft-*`、`tmp-*`、`*.bak`、演示工程 `books/_*`
- 重复拷贝（如 handoff 与源文件名不一致的旧副本）
- 本 playbook 仓库其余源码（除非 README 另列许可证与获取方式）

## 3. README 须像开源项目（可直接传 GitHub）

除「怎么用」外，**必须含书籍介绍**，让访客不看 PDF 也能判断要不要读：

1. 书名、副标题、一段简介 / 承诺（claim）
2. 适合谁、读完能做什么（`reader_before` / `reader_after`）
3. 章节目录（来自 `02_outline.json`）
4. 快速开始（先读 `book.pdf`）与 **从源码到产物**（typst 编译）
5. 仓库结构表、贡献与反馈入口（`workflow/`）
6. License（MIT）

`package_book.py` 会按 `01_立项卡.json` + `config.toml` + outline **自动生成**该 README；特殊说明可另附。

## 3.1 使用约定（README 必写）

1. 解压后先读 `README.md` 与 `MANIFEST.txt`
2. 改正文：优先改 `manuscript/units/`，再 `assemble` 或手改 `typst/chapters/`（两处都有时以 **typst/chapters** 为排版真源，manuscript 为内容真源，并在 README 写明）
3. 重编 PDF：

```bash
cd typst
typst compile --root . main.typ dist/book.pdf
# 或 nu build.nu book（若包内含 build.nu）
```

4. 字体缺失见 `FONTS.md`；装不上字体会回退并告警
5. 反馈写入 `workflow/` 对应模板，勿直接口头交付

## 4. 打包命令

```bash
python3 writing-rules/tools/package_book.py books/<slug> \
  --engine techbook-typst \
  --out dist/<slug>-delivery.tar.gz
```

工具会自动排除 §2 列表并生成 `README.md` + `MANIFEST.txt`。

## 5. 质量门槛

- 解压路径无绝对路径依赖、无指向本机 `~/`
- 无「未使用章节」文件名残留（如已废弃的 `ch1-why.typ`）
- PDF 与 `typst/chapters` 同源可复现（允许字体差异行）
- 体积合理：不含重复 PDF、不打包 `.git`
