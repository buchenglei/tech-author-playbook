# WORKFLOW.md —— 写书工作流（外部 Agent 开工必读）

> **强制入口**：任何会话准备「用 tech-author-playbook 写一本书」之前，必须先读完本文件，并按三角色与四阶段推进。跳过本文件直接写正文，视为未立项写作。

技术规则仍在 `writing-rules/spec/`；本文只规定 **谁在何时做什么、留下哪些文件**。

---

## 0. 最高原则（写作规则怎么定）

1. **写出一本对读者有启发、且符合写作大纲承诺的技术书 = 第一要义。** 流程与门禁为此服务。
2. **规则分两层，融合后执行：**
   - **基线层（必须遵守）**：`writing-rules/spec/` 的 MUST——不虚构与断言分级、禁挂牌表单腔、证据与台账、L2 边界、冻结可追溯、语言底线等。
   - **大纲层（按书特化）**：用户大纲中的篇幅、章节骨架（如七段式）、案例/预期输出密度、语言风格等，**融入基线**写成该书的《写作宪法》，而不是另起一套。
3. **冲突不搞「谁压倒谁」**，走阶段 1《大纲×规范融合评估》：列出基线条 vs 大纲条 → 给出**融合方案**（保留基线 / 大纲覆盖 / 合成新条）→ **人确认**后成为本书必须遵守的统一规则。禁止 Agent 静默删改基线 MUST，也禁止无视大纲写法。
4. **内容禁止省 token。** 写正文严禁「最少 token」「梗概先交差」。省 token 只用于流程噪音（§9）。
5. **禁止流于形式。** 空模板当报告、未填 state 就 frozen、文件齐了就算写完，均为交付事故。
6. **证据与不虚构**是基线层不可放弃的地板；深度靠真实案例与命令输出，不靠编造。

## 0.2 质量优先与硬门禁（本版新增）

质量优先不是口号，而是**不可绕过的顺序**：

```text
立项/合同 → 首批试点（1–3 章）→ 独立读者+编辑审阅 → 人签字（宪法/模式确认）
→ 章循环批量：每 2–3 章一批 → 写作 → 三角色自审 → 章审包 → 人签字（≤10 分钟）
→ 该批才能 frozen → ……循环至全书 → 全稿双终审 → 人签字定稿
```

1. **首批（P1）未人签字，不得进入批量。** 首批至少包含 1–3 章完整正文、spec、读者报告、编辑报告、作者改进方案、写作宪法、融合/篇幅裁定。
1b. **每批都需要人签字（章循环）。** 批量期不是「Agent 一气呵成」：默认每 **2–3 章**一批（`review_every_n_chapters`，人可调），每批出**章审包**交人审、签字、细微调整；签字记录写明「改了什么/裁了什么」，**空签字无效**。只有签字覆盖到的批次才能 `frozen`——每批签字既是质量闸，也是全书一致性的校准点。
1c. **人签 = 宪法修订。** 人对某批的调整是规则更新而非一次性 patch：理由回写 `04_写作宪法.md`，下一批《写作者上下文包》自动带上；发挥被追认→入宪法，被否→记反例。
2. **冻结是审阅动作，不是脚本动作。** 任何脚本只能把状态置为 `checking` 或 `candidate`；`frozen` 只能由审阅者/人确认后写入。禁止批量自动冻结。
3. **人确认不可默示。** `rule_conflict_status=confirmed` 必须有 `human_confirmations.pilot` 的 `by`/`at`；写“用户未反对，视为默示确认”一律 P0。
4. **无人值守只能 draft。** `human_in_loop=false` 时停在 P1，交付状态只能是 `draft`；不得 `ready`、不得全稿冻结。
5. **报告必须可核。** 读者/编辑报告至少 3 条 `文件.md:行号` + 原文引句；引句必须在当前稿命中。4 行报告不再能过 TEAM-04。
6. **证据与代码必须可验。** 台账 schema 合法；spec claims 能回到 E-id；C# 片段通过明显语法/缺括号检查，或显式标 `illustrative`；书稿带 `code/` 时 `quality_gate` 会跑真实 `dotnet build`。PDF 编译 0 error 不等于代码正确。
7. **合同变更人拍板。** 页数/字数/节下限的变更必须由人确认；Agent 只能提交《篇幅偏差裁定》，不能自己把合同改到刚好够。
8. **口径必须在合同钉死（P1 阶段）。** `00_大纲合同.json` 的 `word_count_metric`（字数口径）与 `evidence_policy`（证据承载策略：`body-e-tags` / `spec-mapping` / `visible-markers`）必须写明并经人确认；不钉死会出现同一稿子两种薄厚结论、以及「正文带 E-xxx」与「证据只进台账」互相打架（真实书稿实证）。
9. **尾章不得加速。** `quality_gate` 的 DECAY-01/02/03 按章聚合体量/纪律/证据完整度，对比首 ⅓ 与末 ⅓；量产后半程松劲（骤薄、挂牌回潮、spec 塌缩）是 P0，不是自觉问题。
10. **门禁结论可复核。** 报告写「P0=0/零命中」必须带 `<!-- gate_check: … -->` 回执或引用 `handoff/04_check.json`（`run_gates --write-check` 生成）；与实测不符按 RPT-11 打 P0。合法的后期修订（标识清理、温度修订）在 `workflow/revision_log.jsonl` 登记迁移链，旧报告才可追溯。
11. **交付状态与命名。** `human_confirmations.final` 未签字前交付一律 `draft`（MANIFEST/README 均标注）；「终版/final/ready」命名被 `package_book` 护栏拒绝（`--force-name` 显式承担）。禁止把仓库 README 误当书籍 README 交付。
12. **章末固定块的承载形态必须显式裁决。** 合同 `chapter_blocks_as_headings`（true=检查点小节 / false=行文承载）由 09 融合评估提出、人签字；不声明却在正文用「## 本章标尺/## 落地/## 避坑」这类标题 → QG-06 P0。禁止用默认解释代替人裁决（Avalonia 案例实证）。
13. **阶段-进度守恒。** `phase=P1` 且试点未签字时，试点章之外的完稿单元 ≥3 个即 WF-24 P0——「如实写 P1 但全书量产」同样是未签字量产，不是合规。
14. **工具自改必须回流。** 写作会话自造/修改的脚本（如自建检查器、补丁）须在 `07_项目反哺报告.md` 登记（工具名、改了什么、回流计划），交付包带 `tools/`；报告提到工具改动而 07 仍是空模板 → WF-25。
15. **形式自由 = 申报制。** 合同 `form_freedom: true` 时形式类检查（L-FORM-01/02、LANG-05/11/12）降为 P1 提示，允许为内容质量有意为之；有意偏离写 `workflow/deviations.jsonl`（规则/节/理由），**人签字时逐条裁决**（追认=入宪法 / 收敛=记反例）。未申报、或签了字仍未裁决 → P0（DEV-01/02）。硬线（真实性/证据/禁用词/代码可跑/冻结纪律）永不降级。
16. **章审人读 Markdown。** 批量期人审输入为正文 Markdown + 章审包（不必每批编 PDF）；排版只在冻结批之后批量装配。

硬门禁由 `writing-rules/tools/quality_gate.py` 执行，并接入 `validate_quality.py`（G8）。没有 rule 的新检查用 `WF-*` / `RPT-*` / `EVD-*` / `CODE-*` / `QG-*` / `DECAY-*` / `CTR-*` 前缀，不冒充规范规则。

## 0.1 四个身份

| 身份 | 执行者 | 职责 | 不能做 |
| --- | --- | --- | --- |
| **作者 Author** | Agent | 按规范写稿、收反馈、改稿、维护写作宪法 | 自签读者验证 |
| **读者 Reader** | Agent | 以预设人设初读、写阅读报告、滚动监督文风与共识 | 代替人做最终采纳与 L2 验收 |
| **编辑 Editor** | Agent | 专业审校：结构、正确性、门禁、可出版性 | 无证据的技术判断 |
| **人 User** | 发起任务的人 | 确认人设与共识、采信反馈、定稿、写反哺意见 | — |

**读者人设默认**：10 年研发经验的资深后端工程师。开工时必须向**人**确认或改写，并写入 `04_写作宪法.md`。

### 与三级校验的关系（VER-01 不破）

| 层 | 谁 | 产出 | 可否写「读者验证通过」 |
| --- | --- | --- | --- |
| L1a 模拟读者初读 | 读者 Agent | `01_读者报告-*.md` | **否**（只写「模拟读者意见」） |
| L1b 专业审校 | 编辑 Agent | `02_编辑审校-*.md` | **否** |
| L2 真实读者 / 领域终验 | **仅人** | 人反馈、交接包 `05_unverified` | 只有人能签 |

读者 Agent 与作者严重分歧时，**上报人裁决**；通常不必。

## 1. 四阶段总览

```text
阶段1 样板章（人深度参与）
  作者写第1章 → 读者报告 → 编辑审校 → 人反馈
  → 作者《改进方案+写作计划》→ 人确认 → 四方《写作宪法》

阶段2 章循环批量（人按批参与，2–3 章一批）
  每批：写作（三角色自审轮换）→ 章审包 → 人审签字（含细微调整与偏离裁决）
  → 签字覆盖的批次 frozen → 人的调整回写宪法 → 清理过程记忆（见 §4）

阶段3 全稿评审（人深度参与）
  读者通读终审报告 + 编辑终审报告 → 人评价
  → 作者按总反馈优化全稿

阶段4 定稿与反哺（人确认）
  人确认定稿 → 作者/读者/编辑 + 人 共同写《项目反哺报告》
  → 用于优化 tech-author-playbook 本身
```

阶段状态记在书稿 `workflow/00_阶段状态.json`，由 `quality_gate.py` 硬校验：P1 未人签字不得进入 P2；无人值守只能 draft；`done_units` 必须等于 `outline` 的 frozen 集合。

## 2. 阶段 1：样板章（详细）

1. **作者**：走 S0–S2，只写 C01 各节（spec 先于正文），过 G3；装配为第 1 章。**禁止在 P1 签字前写第 2 章。**  
2. **作者（并行）**：写《大纲×规范融合评估》`templates/09_…`：摘录大纲要求 → 对照基线 MUST → **融合条款**（保留基线 / 大纲覆盖 / 合成新条 / Waiver）→ 待人确认。
3. **读者**：按 `templates/01_读者报告.md` 写 **`01_读者报告-第1章.md`**，至少 3 条 `文件.md:行号 + 原文引句`，并填 `reviewed_revision`。
4. **编辑**：按 `templates/02_编辑审校.md` 写 **`02_编辑审校-第1章.md`**，至少 3 条问题；代码/台账问题附命令与输出。
5. **人**：读「第 1 章 + 两份报告 + **大纲×规范融合评估**」，反馈并**确认融合条款**（成为本书统一写作规则）；在 `00_阶段状态.json` 填写 `human_confirmations.pilot.{confirmed,by,at}`。
6. **作者**：写 `03_作者改进方案.md`（改什么、为何、怎么改、后续写作计划），**待人确认**；确认栏必须勾选并写日期。
7. **四方一致**：产出 `04_写作宪法.md`（人设、文风、结构偏好、禁项、章节节奏），确认栏由人签字。此后阶段 2/3 统一执行；修改宪法须人点头。

> 本阶段交付给人的固定三件套：**第 1 章正文、读者报告、编辑审校**。  
> `quality_gate.py` 会拒绝：P1 未签字进入 P2、`03`/`04` 空模板、`09`/`10` 待复核、`human_in_loop=false` 却全稿冻结。

---

## 3. 阶段 2：章循环批量（人按批签字）

每批（默认 2–3 章，`review_every_n_chapters` 可调）是一个完整短任务：

1. **输入**：《写作者上下文包》`templates/11_…`（宪法 + 合同切片 + 上一批冻结小结 + 术语增量 + 未决偏离）——每批都是新上下文，不背全书历史。
2. **写作**：按大纲写批内各章；**节级**仍执行单元 spec、断言台账、G 门禁。写完切身份自审（读者/编辑轮换，产出 3 行卡与抽检意见，带 `文件:行号 + 引句`）。
3. **产出**：本批《章审包》`templates/10_…`（正文 Markdown + 3 行卡 + 新增断言/证据计数 + 偏离登记 ≤3 条 + 自审发现）。
4. **人审签字（≤10 分钟/批）**：读 Markdown 正文 → 裁决偏离（追认/收敛）→ 细微调整 → 签字。签字记录（`00_阶段状态.json` 的 `chapter_signoffs`）必须写明**改了什么/裁了什么**，空签字无效。
5. **冻结**：签字覆盖的批次才能 `frozen`；作者/脚本只能置 `checking`/`candidate`。冻结记录写入 `05_章节滚动评估.md`。
6. **回写**：人的调整回写 `04_写作宪法.md`（规则更新，非一次性 patch）；被追认的偏离入宪法，被否的记反例；更新术语表与上一批小结。
7. **清记忆**：每批跑 `tools/memory_maint.py books/<slug>`（见 §4）。
8. **并行**：人审第 N 批时可写第 N+1 批草稿，但未签字批次不得 `frozen`、不得作为后续批的定稿依赖（只可引用其草稿内容，回改走 revision）。

## 4. 清理过时记忆与负担（每轮读者回合后）

**可清/可归档**：过程闲聊、废弃草稿、重复试写、已解决的临时笔记、超长工具输出。

**禁止删**：`01–08` 标准文件、`units/*` 冻结稿、`handoff/`、台账与术表、`04_写作宪法.md`、各类报告、`00_阶段状态.json`。

做法：

```bash
python3 writing-rules/tools/memory_maint.py books/<slug>          # 归档 draft-*.md 等
python3 writing-rules/tools/memory_maint.py books/<slug> --dry-run
```

```text
workflow/memory/CURRENT.md   ← 当前窗口摘要（工具生成）
workflow/archive/            ← 旧草稿与过程
```

每轮结束把「本章结论 5 行内」追加进状态文件 `notes_brief`，避免上下文越滚越重。

---

## 5. 阶段 3：全稿评审

1. **读者**：通读全稿，出最终阅读评估（仍用 01 模板，标注 `scope=full`）。  
2. **编辑**：全稿审校 + 红线检查，出终审意见。  
3. **人**：读全稿与两份终审，给总反馈。  
4. **作者**：按总反馈做全稿优化（范围、结构、文风、事实），更新交接包；交付状态仍按 TEAM-07（未完成 L2 只能 `draft`）。

---

## 5.5 质量与体量验收（冻结 / 交付前）

- 页数/总字量落在 `00_大纲合同.json`；单节实写字数 ≥ 合同下限，**禁止梗概充数**。
- 实战书章节检查：落地命令与**预期输出**、避坑/案例是否满足大纲块要求。
- 阶段状态、frozen、gates、报告文件四者一致。

## 6. 阶段 4：定稿与项目反哺

1. **人**书面确认「定稿」。  
2. 三角色 + 人共同填写 `templates/07_项目反哺报告.md`：各写「使用中的问题 → 影响 → 优化建议」；人在对应位置补真实反馈。  
3. 将结论回写本仓库：`PROBLEMS.md` / 规范 / 工具（另开维护变更，按根 `AGENTS.md`）。

## 6.5 交付物（tar.gz）

人工交付以 **`.tar.gz`** 为准。清单与排除项见 [`templates/08_交付规范.md`](templates/08_交付规范.md)；打包：

```bash
python3 writing-rules/tools/package_book.py books/<slug> --engine techbook-typst
```

必含：`README.md`、`book.pdf`、`typst/` 可编译工程、`manuscript/`、`handoff/`、`workflow/` 报告、`MANIFEST.txt`。

## 8. 自由区（申报制发挥：放开 4 项，人逐批校准方向）

在**硬地板**之上，下列 4 项由作者**为内容质量自由发挥**（合同 `form_freedom: true` 生效）：

| 自由区（章级，放开） | 例 |
| --- | --- |
| 章节引入方式 | 故事 / 问题 / 对话 / 场景直入；叙述顺序、章法开合 |
| 表格与图的使用密度 | 能写成推演就不强行出表；图表多少按本章内容定 |
| 句长/段长上限 | 60 字句长、6 句段长降为**建议值**，允许为节奏突破 |
| 示例题材、叙事口吻、幽默密度 | 按本章主题选题材与语气；幽默上限放开 |

**书级结构不逐章放开**（全书节奏要统一，走 09/合同**整书一次裁决**）：章末固定块形态（`chapter_blocks_as_headings`）、附录与专栏形态、术语命名时机。

**申报制（发挥的代价是留痕）**：

1. 有意突破形式规则 → 写入 `workflow/deviations.jsonl`（规则 ID / 节 / 理由），机器把形式类检查降为 P1 提示；
2. 人签字时**逐条裁决**：追认（入宪法，后续照此发挥）/ 收敛（记反例，后续不再出现）；
3. 未申报的形式偏离、或签字时仍有未裁决的偏离 → P0（DEV-01）。

**硬地板（永不放开）**：不虚构与断言分级、台账可回溯、禁用词、代码可跑、L2 不代签、冻结可追溯、交接包诚实。

评价只看**读者体验**（生硬/套模板/说清/流畅/想读）与**内容深度**，不要求「像我们的样章」；发挥跑偏由人签字收敛，而不是事先禁止。
