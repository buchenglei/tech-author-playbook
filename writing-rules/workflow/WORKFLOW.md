# WORKFLOW.md —— 写书工作流（外部 Agent 开工必读）

> **强制入口**：任何会话准备「用 tech-author-playbook 写一本书」之前，必须先读完本文件，并按三角色与四阶段推进。跳过本文件直接写正文，视为未立项写作。

技术规则仍在 `writing-rules/spec/`；本文只规定 **谁在何时做什么、留下哪些文件**。

---

## 0. 最高原则（写作规则怎么定）

1. **写出一本对读者有启发、且符合写作大纲承诺的技术书 = 第一要义。** 流程与门禁为此服务。
2. **规则分两层，融合后执行：**
   - **基线层（必须遵守）**：`writing-rules/spec/` 的 MUST——不虚构与断言分级、禁挂牌表单腔、证据与台账、L2 边界、冻结可追溯、语言底线等。
   - **大纲层（按书特化）**：用户大纲中的篇幅、章节骨架（如七段式）、案例/预期输出密度、语言风格等，**融入基线**写成该书的《写作宪法》，而不是另起一套。
3. **冲突不搞「谁压倒谁」**，走阶段 1《大纲×规范融合评估》：列出基线条 vs 大纲条 → 给出**融合方案**（保留基线 / 大纲覆盖 / 合成新条）→ **人确认**后成为本书必须遵守的统一规则。禁止 Agent 静默删改基线 MUST，也禁止无视大纲写法。
4. **内容禁止省 token。** 写正文严禁「最少 token」「梗概先交差」。省 token 只用于流程噪音（§9）。
5. **禁止流于形式。** 空模板当报告、未填 state 就 frozen、文件齐了就算写完，均为交付事故。
6. **证据与不虚构**是基线层不可放弃的地板；深度靠真实案例与命令输出，不靠编造。

## 0.2 质量优先与硬门禁（本版新增）

质量优先不是口号，而是**不可绕过的顺序**：

```text
立项/合同 → 只写 1 章试点 → 独立读者+编辑审阅 → 人签字
→ 才允许批量写作 → 每章审阅后才能冻结 → 全稿双终审 → 人签字定稿
```

1. **P1 未人签字，不得进入 P2。** 试点章至少包含 1–2 节完整正文、spec、读者报告、编辑报告、作者改进方案、写作宪法、融合/篇幅裁定。
2. **冻结是审阅动作，不是脚本动作。** 任何脚本只能把状态置为 `checking` 或 `candidate`；`frozen` 只能由审阅者/人确认后写入。禁止批量自动冻结。
3. **人确认不可默示。** `rule_conflict_status=confirmed` 必须有 `human_confirmations.pilot` 的 `by`/`at`；写“用户未反对，视为默示确认”一律 P0。
4. **无人值守只能 draft。** `human_in_loop=false` 时停在 P1，交付状态只能是 `draft`；不得 `ready`、不得全稿冻结。
5. **报告必须可核。** 读者/编辑报告至少 3 条 `文件.md:行号` + 原文引句；引句必须在当前稿命中。4 行报告不再能过 TEAM-04。
6. **证据与代码必须可验。** 台账 schema 合法；spec claims 能回到 E-id；C# 片段通过明显语法/缺括号检查，或显式标 `illustrative`；书稿带 `code/` 时 `quality_gate` 会跑真实 `dotnet build`。PDF 编译 0 error 不等于代码正确。
7. **合同变更人拍板。** 页数/字数/节下限的变更必须由人确认；Agent 只能提交《篇幅偏差裁定》，不能自己把合同改到刚好够。

硬门禁由 `writing-rules/tools/quality_gate.py` 执行，并接入 `validate_quality.py`（G8）。没有 rule 的新检查用 `WF-*` / `RPT-*` / `EVD-*` / `CODE-*` / `QG-*` 前缀，不冒充规范规则。

## 0.1 四个身份

| 身份 | 执行者 | 职责 | 不能做 |
| --- | --- | --- | --- |
| **作者 Author** | Agent | 按规范写稿、收反馈、改稿、维护写作宪法 | 自签读者验证 |
| **读者 Reader** | Agent | 以预设人设初读、写阅读报告、滚动监督文风与共识 | 代替人做最终采纳与 L2 验收 |
| **编辑 Editor** | Agent | 专业审校：结构、正确性、门禁、可出版性 | 无证据的技术判断 |
| **人 User** | 发起任务的人 | 确认人设与共识、采信反馈、定稿、写反哺意见 | — |

**读者人设默认**：10 年研发经验的资深后端工程师。开工时必须向**人**确认或改写，并写入 `04_写作宪法.md`。

### 与三级校验的关系（VER-01 不破）

| 层 | 谁 | 产出 | 可否写「读者验证通过」 |
| --- | --- | --- | --- |
| L1a 模拟读者初读 | 读者 Agent | `01_读者报告-*.md` | **否**（只写「模拟读者意见」） |
| L1b 专业审校 | 编辑 Agent | `02_编辑审校-*.md` | **否** |
| L2 真实读者 / 领域终验 | **仅人** | 人反馈、交接包 `05_unverified` | 只有人能签 |

读者 Agent 与作者严重分歧时，**上报人裁决**；通常不必。

## 1. 四阶段总览

```text
阶段1 样板章（人深度参与）
  作者写第1章 → 读者报告 → 编辑审校 → 人反馈
  → 作者《改进方案+写作计划》→ 人确认 → 四方《写作宪法》

阶段2 滚动产出（人不参与）
  按大纲写稿（节级门禁仍跑）
  每完成「默认3章，可按卷/章约定」→ 读者评估 → 作者自评并调思路
  每轮后：清理过时过程记忆（见 §4）

阶段3 全稿评审（人深度参与）
  读者通读终审报告 + 编辑终审报告 → 人评价
  → 作者按总反馈优化全稿

阶段4 定稿与反哺（人确认）
  人确认定稿 → 作者/读者/编辑 + 人 共同写《项目反哺报告》
  → 用于优化 tech-author-playbook 本身
```

阶段状态记在书稿 `workflow/00_阶段状态.json`，由 `quality_gate.py` 硬校验：P1 未人签字不得进入 P2；无人值守只能 draft；`done_units` 必须等于 `outline` 的 frozen 集合。

## 2. 阶段 1：样板章（详细）

1. **作者**：走 S0–S2，只写 C01 各节（spec 先于正文），过 G3；装配为第 1 章。**禁止在 P1 签字前写第 2 章。**  
2. **作者（并行）**：写《大纲×规范融合评估》`templates/09_…`：摘录大纲要求 → 对照基线 MUST → **融合条款**（保留基线 / 大纲覆盖 / 合成新条 / Waiver）→ 待人确认。
3. **读者**：按 `templates/01_读者报告.md` 写 **`01_读者报告-第1章.md`**，至少 3 条 `文件.md:行号 + 原文引句`，并填 `reviewed_revision`。
4. **编辑**：按 `templates/02_编辑审校.md` 写 **`02_编辑审校-第1章.md`**，至少 3 条问题；代码/台账问题附命令与输出。
5. **人**：读「第 1 章 + 两份报告 + **大纲×规范融合评估**」，反馈并**确认融合条款**（成为本书统一写作规则）；在 `00_阶段状态.json` 填写 `human_confirmations.pilot.{confirmed,by,at}`。
6. **作者**：写 `03_作者改进方案.md`（改什么、为何、怎么改、后续写作计划），**待人确认**；确认栏必须勾选并写日期。
7. **四方一致**：产出 `04_写作宪法.md`（人设、文风、结构偏好、禁项、章节节奏），确认栏由人签字。此后阶段 2/3 统一执行；修改宪法须人点头。

> 本阶段交付给人的固定三件套：**第 1 章正文、读者报告、编辑审校**。  
> `quality_gate.py` 会拒绝：P1 未签字进入 P2、`03`/`04` 空模板、`09`/`10` 待复核、`human_in_loop=false` 却全稿冻结。

---

## 3. 阶段 2：滚动产出（含并行）

1. 按大纲继续写；**节级**仍执行单元 spec、断言台账、G 门禁。**没有审阅记录的节不得 `frozen`。**  
2. **混合评审节奏**：每章交 **3 行卡**（见 `templates/05` §A）；每 **N 章详评**（默认 3，可按卷/章约定）。卡点「阻断」→ 立即详评。  
3. **并行 N+1**：作者写第 N+1 章时，读者可评第 N 章；反馈只约束未冻结部分，不回改冻结章（走 revision）。  
4. **读者职责**：人设视角监督是否死板/套模板/违宪法/读不下去；**不代替人决定**。报告同样要带 `文件:行号 + 引句`。  
5. **编辑抽检**：每 N 章至少一次编辑审校，重点代码、台账、结构；不能只靠读者。  
6. **作者**：读卡与详评，决定是否调后续思路；严重分歧 → `blockers` 等人。  
7. **冻结**：作者只能置 `checking`/`candidate`；审阅者确认后写入 `frozen`，并在 `05_章节滚动评估.md` 留记录。  
8. **清记忆**：每轮跑 `tools/memory_maint.py books/<slug>`（见 §4）。

---

## 4. 清理过时记忆与负担（每轮读者回合后）

**可清/可归档**：过程闲聊、废弃草稿、重复试写、已解决的临时笔记、超长工具输出。

**禁止删**：`01–08` 标准文件、`units/*` 冻结稿、`handoff/`、台账与术表、`04_写作宪法.md`、各类报告、`00_阶段状态.json`。

做法：

```bash
python3 writing-rules/tools/memory_maint.py books/<slug>          # 归档 draft-*.md 等
python3 writing-rules/tools/memory_maint.py books/<slug> --dry-run
```

```text
workflow/memory/CURRENT.md   ← 当前窗口摘要（工具生成）
workflow/archive/            ← 旧草稿与过程
```

每轮结束把「本章结论 5 行内」追加进状态文件 `notes_brief`，避免上下文越滚越重。

---

## 5. 阶段 3：全稿评审

1. **读者**：通读全稿，出最终阅读评估（仍用 01 模板，标注 `scope=full`）。  
2. **编辑**：全稿审校 + 红线检查，出终审意见。  
3. **人**：读全稿与两份终审，给总反馈。  
4. **作者**：按总反馈做全稿优化（范围、结构、文风、事实），更新交接包；交付状态仍按 TEAM-07（未完成 L2 只能 `draft`）。

---

## 5.5 质量与体量验收（冻结 / 交付前）

- 页数/总字量落在 `00_大纲合同.json`；单节实写字数 ≥ 合同下限，**禁止梗概充数**。
- 实战书章节检查：落地命令与**预期输出**、避坑/案例是否满足大纲块要求。
- 阶段状态、frozen、gates、报告文件四者一致。

## 6. 阶段 4：定稿与项目反哺

1. **人**书面确认「定稿」。  
2. 三角色 + 人共同填写 `templates/07_项目反哺报告.md`：各写「使用中的问题 → 影响 → 优化建议」；人在对应位置补真实反馈。  
3. 将结论回写本仓库：`PROBLEMS.md` / 规范 / 工具（另开维护变更，按根 `AGENTS.md`）。

---

## 6.5 交付物（tar.gz）

人工交付以 **`.tar.gz`** 为准。清单与排除项见 [`templates/08_交付规范.md`](templates/08_交付规范.md)；打包：

```bash
python3 writing-rules/tools/package_book.py books/<slug> --engine techbook-typst
```

必含：`README.md`、`book.pdf`、`typst/` 可编译工程、`manuscript/`、`handoff/`、`workflow/` 报告、`MANIFEST.txt`。
排除：日志、archive、DS_Store、draft-*/tmp-*、smoke 产物。包须干净、可离线改、可重编 PDF。

## 8. 自由区（作者可发挥，不设死）

在**硬地板**之上，下列项目由作者自选，**允许与样章不一致**：

| 自由区 | 例 |
| --- | --- |
| 叙述顺序 | 先故事后点题、双线交错、倒叙复盘 |
| 修辞与节奏 | 设问密度、比喻、幽默、长短句章法 |
| 章法开合 | 钩子怎么起、留白多少、是否用「N 处会判断错」骨架 |
| 图表取舍 | 能写成推演就不强行出表；表≤2 仍是底线 |
| 标题气质 | 问题式 / 发现式 / 动作式，只要不挂牌 |

**实验配额**：每章 1–2 处风格实验，在《写作宪法》或滚动评估「偏离记录」记一句；读者回合决定保留或收敛。

**硬地板（不放开）**：不虚构与断言分级、台账可回溯、L2 不代签、冻结可追溯、交接包诚实、禁挂牌表单腔、禁用词。

评价只看**读者体验**（生硬/套模板/说清/流畅/想读），不要求「像我们的样章」。

## 9. Token 与速度纪律（**仅限流程开销，不适用正文**）

**正文与案例禁止省 token（§0.3）。** 下列节约**只针对过程噪音**：

- **默认只读 [`briefs/`](briefs/README.md) 加载卡**；需要细则再开 `spec/` 单章。
- 校验用 `tools/run_gates.py`（紧凑输出）；不要每次贴全文 registry。
- 写正文不读 `techbook-typst/AGENTS.md`；文风只读书内 `07_style.kernel.md`。
- 新单元用 `tools/new_unit.py` 预填 spec，勿从 outline 手抄。
- 3 行卡禁止写成小作文；详评只在每 N 章或升级时。
- 并行 N+1：用读者 3 行卡喂下一章，而不是等详评堵在半路。

## 10. 开工检查表（Agent 自检）

- [ ] 已读本文件与 `roles/` 三份人格  
- [ ] 已向人确认读者人设与节奏（默认 10 年资深后端；每 3 章）  
- [ ] 书稿下已有 `workflow/`（或用 `init_book.py` 新建）  
- [ ] **P1 只写第 1 章；`human_confirmations.pilot` 已由人签字，才允许 P2**  
- [ ] 阶段 1 未跳过「人采信」就写宪法  
- [ ] 任何报告都未把 L1a/L1b 写成 L2 通过  
- [ ] 没有任何脚本自动写 `frozen`；冻结有审阅记录  
- [ ] 读者/编辑报告至少 3 条 `文件:行号 + 原句`，且 `reviewed_revision` 是当前稿  
- [ ] C# 片段已编译，或显式标 `illustrative`；没有用 PDF 0 error 冒充代码正确
