# 如何改规范（writing-rules）

写作规范是**可判定的门禁源**，不是随笔。改它等于改所有书稿的验收线。动笔前读完本页。

## 先分清你在改什么

| 类型 | 例子 | 必须同步 |
| --- | --- | --- |
| **条文措辞** | 说清一条已有规则 | 规则 ID 不变；跑 registry |
| **新增规则** | 增加 MUST/SHOULD | 新 ID + 判定方式 + 失败动作；更新总表 |
| **阈值** | 句长 60 字 | 同步 `tools/spec_lint.py` 常量 + `F-待校准项.md` |
| **门禁行为** | G2 查 bridge | 同步 `spec_lint.py` + `C-门禁速查.md` + 测试 |
| **kit 模板** | 立项卡字段 | 同步 `kit/` 与 `B-模板索引.md` |

## 硬约束

1. **单一真源**：规则定义只写在 `spec/0x-*.md` 正文里。`A-规则总表.md` 由脚本派生，手改会被覆盖。
2. **MUST 必须可判定**：写清「谁判 / 用什么判 / 判不过怎样」。给不出判定方式就降级 SHOULD（RULE-01）。
3. **不要写死托管平台 URL**：来源用 `https://…` 或 `repo:相对路径`。
4. **阈值要有校准路径**：经验值写进 `F-待校准项.md`，并留回填计划。
5. **单元门禁 ≠ 发布红线**：MUST 管「这节能不能冻结」；发布红线见 `08-校验.md` 十条。不要再把一百多条都当红线。

## 标准改法

```text
1. 在 spec/ 对应分片改正文（含 **ID**（强度｜判定｜失败动作））
2. python3 tools/build_spec.py --write /tmp/spec.md     # 本地通读
3. python3 tools/spec_lint.py spec/ --registry --write  # 重写附录 A
4. python3 tools/tests/run_tests.py                     # 工具回归
5. 对金样板跑 G0–G3、G5–G7（G4 未实现；G8 对结构样板预期红）
```

## 规则 ID 命名

- 域前缀：`RULE ENG TOP AUD STR UNIT DEM LANG HUMOR FMT CITE TIME VER BOOK TEAM`
- 形如 `STR-08`，两位数字，全库唯一。
- 删除规则不要复用 ID；在变更说明里标 `deprecated`。

## 强度与失败动作

| 强度 | 失败动作 | 含义 |
| --- | --- | --- |
| MUST | 阻断 | 不过则单元不能冻结 / 门禁失败 |
| SHOULD | 登记 | 记录并纳入 review，不阻断 |
| MAY | — | 不写进总表也可 |

MUST 配「登记」是自相矛盾，脚本会报 `S-RULE-05`。

## 阈值改动

改动 `MAX_SENT` / `MAX_PARA_SENTS` 等时：

1. 改 `tools/spec_lint.py` 顶部常量；
2. 在 `F-待校准项.md` 记录旧值、新值、依据（几本书、多少单元）；
3. 用金样板 12 单元重跑 lint，把命中差异写进 PR。

## 金样板是回归夹具

`books/how-to-write-a-tech-book/` 不只是教材。规范变严变松，都应在这里可观察。新修工具 bug 时，在 `tools/tests/` 补负例（见 `PROBLEMS.md`）。

## PR 里请写清

- 动机（哪类失效没拦住 / 哪类误报）
- 条文 diff 摘要（规则 ID 列表）
- 验证：`run_tests.py` 输出摘要 + 金样板门禁退出码
- 若改阈值：样本来源与代价
