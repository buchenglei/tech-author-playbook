# 交接包 README —《如何写一本技术书》

## 这是什么书

一本实战型方法书。承诺：技术书读不下去的主因不是知识深度不够，而是承诺不可验证、章节并列无递进、断言无来源；用可验证承诺、现象/机制/代价三层骨架与 E0–E3 断言分级约束生产，读者按目录跳读也能完成既定任务。

## 给谁

写过技术文章、想把文章装订成书的工程背景作者。假设你懂 Markdown、能跑脚本。不假设你做过出版，也不假设你熟悉 Typst。

## 怎么读

- 线性通读：C01 → C02 → C03 → C04
- 只定选题：C01-S3 → C02-S1…S3
- 只体检目录：C01-S2 → C01-S3 → C03-S1 → C03-S3

## 怎么验收

1. 读 `02_glossary.json`，确认术语一致。
2. 读 `03_ledger.csv`，抽查 E-001、E-004、E-014 是否可溯源。
3. 读 `05_unverified.md`，把未验证项当风险清单，不要当免责声明。
4. 用正文的 P1–P6 判据勾一遍你自己的书稿目录。
