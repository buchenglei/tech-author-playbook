# 读者假设表（S1 / §2）

每条标 `given / inferred / assumed`。`assumed` 不得支撑比较级。

## 1. 假设表

| # | 假设 | 标记 | 依据 | 能支撑的写法 |
|---|---|---|---|---|
| A1 | 读者写过至少一篇带代码或配置的技术文章 | inferred | 本书定位为「把文章装订成书」，无写作经验者买不到这本书 | 可直陈，注明这是入口假设 |
| A2 | 读者未把多篇技术文系统装订成书 | inferred | 样书与选题均针对「首次成书」 | 可直陈 |
| A3 | 读者能读懂中文技术文档，不依赖翻译 | given | 书稿语言为中文 | 可直陈 |
| A4 | 读者愿意跑命令行脚本并读退出码 | assumed | 未测试真实读者工具链 | 只能写条件句：「若你已习惯跑脚本……」 |
| A5 | 读者对 Typst/LaTeX 无预设 | assumed | 排版已划入 scope_out | 条件句；不比较「比 Word 简单」 |
| A6 | 读者以中文写作 | inferred | 语言规则与标点均按中文 | 可直陈 |

**assumed 占比**：2/6，属少数。正文可直陈 inferred 项；A4、A5 用条件句，交接包列为待验证（AUD-03）。

## 2. 起点能力清单

开始读第 1 章之前，你应该能：

- 用 Markdown 写完一篇带标题与代码块的千字技术文
- 读一份开源仓库的 README 与目录，并说出各文件用途
- 在终端执行脚本，能说出退出码 0 与非 0 的差别

做不到第一条，先写三篇短文再回来。做不到第二条，先读两个中型仓库的 `docs/`。做不到第三条，先补 shell 的重定向与退出码。

## 3. 读后可完成的动作

- 写出一句可证伪的书稿承诺，并据此给出 scope_in / scope_out
- 把承诺拆成卷—章—节，每章标出独立产出与现象/机制/代价职责
- 按断言分级写完一个写作单元并通过门禁，交出可复检的交接包

## 4. 未验证声明

- 未做真实读者试读；未测「30 分钟内能否写完立项卡」。
- A4（工具链意愿）与 A5（排版无预设）是 assumed，若读者占比与假设相反，前言需改条件式。
