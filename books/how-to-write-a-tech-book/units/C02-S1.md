# 主题名不是承诺

「讲清楚 Kubernetes」不是承诺，是主题。主题划定讨论对象，不说明读者读完后的变化。上一章的预判判据 P1 要求前言有一句可被证据推翻的承诺；主题名推不翻，因为它什么也没断言。

## 现象：书名像口号，前言像目录

在选题会上，常见开场是「这本书讲透连接池」。听的人点头，散会后仍不知道读完能做什么。若追问「怎么算讲透」，回答常是「把参数都讲到」。参数讲完了，读者仍不会在生产里改一个数。

## 机制：主题与承诺差在「可观察的变化」

| 句型 | 类型 | 能否被推翻 |
| --- | --- | --- |
| 讲清楚 X | 主题 | 否 |
| 深入理解 X | 主题 | 否 |
| 读完能独立部署无状态服务 | 承诺 | 能：部署失败即未兑现 |
| 读完能用借出/占用/归还三段区分泄漏 | 承诺 | 能：区分不出即未兑现 |

承诺把读者的变化写成动作。动作可被第三方观察，于是可以对账。

## 证据：规范用 TOP-01 卡主题句

规范要求 claim 可证伪，判据是句中出现具体机制、条件或因果，且能构造反例（E-006）。写不出反例的句子，多半在描述领域而不是描述变化。

Diátaxis 同样按读者任务而不是学科目录组织材料（E-001）。任务句比学科句更接近承诺。

## 代价：写细承诺会得罪范围

「能独立部署」比「讲清楚」窄。窄的代价是部分读者被划到书外。这个代价值得付：无法核对的宽承诺，获客靠标题，留客靠运气。

## 改写对照

| 不合格 | 合格 | 多了什么 |
| --- | --- | --- |
| 讲透消息队列 | 读完能根据积压与再平衡策略定位八成消费延迟 | 观察量与动作 |
| 深入理解锁 | 读完能说出可重入锁失效的三个条件并写出复现 | 条件与产物 |
| 写作方法大全 | 读完能交出通过门禁的一个单元 | 交付物 |

## 误区：用读者画像冒充承诺

「写给进阶工程师」只说明受众，不说明变化。受众句可以放在前言，但不能替代承诺句。

## 收束

对照表给出了形状，没给出完整写法。承诺还要和范围、否决信号绑在一起，才挡得住下一节的范围失控。
