# 范围失控的代价

范围失控很少在立项那天发生。它发生在写作中段：每多查一份资料，就多一个「值得写进书里」的角落。作者多写两章觉得赚了；读者在目录上多读两行，已经决定不买。

## 现象：膨胀听起来像尽责

「既然讲了 A，不讲 B 不完整」是最常见的扩写理由。B 写完又牵出 C。等到目录打印出来，承诺句还停在原来的边界，章却多了三块。这时作者面临两个选择：把承诺改宽，或把三块删掉。

改宽更快，于是链条启动。膨胀从一句体谅开始，以一本失去边界的书结束。过程里每一步都有理由，合起来却没有新的承诺。

## 机制：结算点不在作者

作者的结算单位是「写完了没有」。读者的结算单位是「换到位移没有」。范围膨胀不推迟作者的完工日，却推迟读者的位移——中间多出来的章与承诺无关。

推断：多数读者不会投诉「多写了两章」，他们直接不读（未实测）。可观察的是：目录变长之后，任务型读者会改用电子书检索，放弃线性阅读。

## 证据：规范把代价写成停手表

否决信号里有三条直接对应膨胀：承诺过宽、增量不具体、时效过短（E-008）。篇幅预算超支时的三选一是：砍范围、拆章、上调全书预算并说明代价。默认超预算是违规的。

## 三种处置

| 处置 | 做法 | 账单 |
| --- | --- | --- |
| 砍范围 | 从 scope_in 删除，并写进 scope_out | 损失话题覆盖 |
| 拆书 | 新书立项，共用部分作附录 | 两本书的交付压力 |
| 上调预算 | 重算 target_words，并声明读者成本 | 读者时间变长 |

没有免费选项。把账单写清楚再选，好过在交稿前偷偷加厚。

## 停手表

以下任一成立，停手而不是继续写：

- 章目录每改一版，claim 要跟着改一次
- 已写章里有两章无法写进一句「对应 claim 的哪一点」
- 新增小节的理由是「资料都在这了」

停手动作是回到立项卡，改 scope 或 kill_criteria，再继续。不是「先写完再说」。

## 代价：停表会打断心流

停表意味着这周不产新字数。接受它。链甲的起点是承诺，承诺漂了还在写，后面每一页都可能作废。

## 误区：用附录收纳失控内容

附录不是范围外内容的收容所。与 claim 无关的材料进附录，读者仍会在目录上付注意力税。无关就删。

## 收束

范围停住了，承诺才算数。下一章把承诺拆成能跳读的目录——拆法错了，对称结构会重新把书拖回汇编。
