# 断言分级到冻结

上一节说自证太便宜。替代方案不是「更认真」，是换记账方式：每条事实断言定级、进台账，一节过完门禁才标冻结。冻结之后只许走变更登记，不许静默改字。

## 先写句子再补来源，会追着句子找出处

人的默认顺序是想到什么写什么，写完再核对。句子一旦生成，作者会为它寻找来源。于是来源追着句子，而不是句子追着来源。最典型的痕迹是：出处写成文档首页，locator 空泛。

## 分级绑句式，不绑态度

| 级 | 含义 | 允许写法 | 不允许 |
| --- | --- | --- | --- |
| E0 | 本机实测，有命令与输出 | 直陈，附环境 | 省略环境 |
| E1 | 一手来源：文档、源码、规范 | 直陈，附版本与 locator | 写成「一般认为」 |
| E2 | 二手转述 | 「有资料提到……（来源）」 | 直陈 |
| E3 | 推断，无外部依据 | 「推断：……（未实测）」 | 直陈 |

（E-013）

等级决定句子长什么样。这样堵住的是「把推断伪装成事实」：E3 句子若缺「推断/推测/未实测」，脚本直接打回。

台账一行长这样：

```text
E-013,默认池上限是 10,E1,官方文档,https://example.invalid/docs,v8.0,§Pool,,,2026-10-20,C04-S2
```

字段包括断言、等级、来源、locator 与单元号。数字要能对上编号，命令要能重跑。

生成顺序是：证据 → 机制 → 代价 → 现象 → 误区 → 收束。开头最后写。先写开头会为了圆开头扭曲证据。

## 冻结八项

| # | 项 | 要点 |
| --- | --- | --- |
| 1 | 只回答 question | 跑题即不合格 |
| 2 | produces 已交付 | 读者拿到了东西 |
| 3 | 六个位置齐全且不挂牌 | 代价不得为空 |
| 4 | 三层有承接 | 不是并列 |
| 5 | 数字可回溯 | 挂 E 编号 |
| 6 | 代码执行过 | 带 src 或命令 |
| 7 | 语言指标过 | lint 退出码 |
| 8 | 节尾留钩 | 指向下一节 |

八项全过，才在 state 里把 status 改成 frozen。改 frozen 不是心理动作，是文件动作。

claims 先于正文，E-013 指向写作规范的断言来源等级表。推断句已标「未实测」。冻结前跑 `spec_lint --profile manuscript`。

记账会挡住灵感型写作：想写的句子若没有来源，要么去查，要么降级，要么删。买的是发布时不必逐句翻旧账。版本也会漂移：文档改版后 locator 失效，所以台账要有 date 与 review_by。

把什么都写成 E3，整本书会变成猜想集。E3 必须限量，且句子里必须看得见等级。

冻结有了纪律，还剩清单：哪些事不能拖到「以后」。
