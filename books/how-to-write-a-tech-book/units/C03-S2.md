# 三层怎么落到节上

上一节拆掉假整齐，留下一个空：正确的章内结构长什么样。答案不是又一个模板，是三层剥法。每一层回答不同的问题，合起来才构成「论述」而不是「资料」。三层是你的写作脚手架，不是读者看到的挂牌目录。

## 只讲一层的章，会塌成某种文体

只罗列症状，读者不知道为什么，也不会选。只讲内部，读者对不上自己的问题。只讲风险，像劝退文。缺任一层，章就塌成某一类文体。

现象要略带意外。平铺的「背景介绍」不是现象，是目录换了个位置。

机制是篇幅主体。建议机制占比不低于三成、不高于七成。低于三成讲不清，高于七成读者被细节淹。

代价不得为空。每节至少写一条「本节结论在什么条件下失效」。找不到代价，通常说明结论被夸大。

## 先写证据，后写开头

| 阅读顺序 | 生成次序 |
| --- | --- |
| 现象 | 4 |
| 机制 | 2 |
| 证据 | 1 |
| 代价 | 3 |
| 误区 | 5 |
| 收束 | 6 |

（E-010）

先写开头，作者会为了圆开头扭曲证据。这是最常见的失真路径。证据先落盘，机制才有约束。写完之后做「去壳检查」：抽掉表格与编号，是否仍是一条能跟着走的推演。

## 职能要齐，标题要融

一章不必刚好三节，但三种职能都要能被指认。role 字段在 outline 里显式记账，缺一不可。成文却禁止写成「现象：/机制：/代价：」三块牌子（UNIT-21）——读者要的是经历这条链，不是填这张表。

本章自己就是这么做的：上一节从「目录太整齐」的怪感起头，本节拆切法，下一节给检验。读者跳着读也能各取一层。

三层不是万能语法。叙事型案例、历史演进型章节强行三层会拧巴。这类章按主导职能标注 role，其余层以段落形式存在。规则管的是「三种职能齐备」，不是「三个小标题」。

小结冒充不了代价层。小结复述前文，不回答失效条件。代价层必须引入新的信息：边界、反例、取舍表。
