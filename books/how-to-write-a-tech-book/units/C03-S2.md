# 现象机制代价怎么拆

上一节拆掉假整齐，留下一个空：正确的章内结构长什么样。答案不是又一个模板，是三层剥法。每一层回答不同的问题，合起来才构成「论述」而不是「资料」。

## 现象：只讲机制的章像手册，只讲现象的章像博客

只罗列症状，读者不知道为什么，也不会选。只讲内部，读者对不上自己的问题。只讲风险，像劝退文。缺任一层，章就塌成某一类文体。

## 机制：三层的职责

| 层 | 回答什么 | 读者拿到什么 |
| --- | --- | --- |
| 现象层 | 有什么可观察的怪事 | 一个愿意往下问的起点 |
| 机制层 | 为什么会这样 | 拆开后的关键路径 |
| 代价层 | 什么条件下结论失效 | 可执行的取舍依据 |

现象要略带意外。平铺的「背景介绍」不是现象，是目录换了个位置。

机制是篇幅主体。规范建议机制占比不低于三成、不高于七成。低于三成讲不清，高于七成读者被细节淹。

代价不得为空。每节至少写一条「本节结论在什么条件下失效」。找不到代价，通常说明结论被夸大。

## 生成顺序：先写证据，后写开头

| 阅读顺序 | 生成次序 |
| --- | --- |
| 现象 | 4 |
| 机制 | 2 |
| 证据 | 1 |
| 代价 | 3 |
| 误区 | 5 |
| 收束 | 6 |

（E-010）

先写开头，作者会为了圆开头扭曲证据。这是最常见的失真路径。证据先落盘，机制才有约束。

## 落到节上

一章不必刚好三节，但三种职能都要能被指认。

示例（本章自指）：

| 节 | 职能 | 产出 |
| --- | --- | --- |
| C03-S1 对称目录 | 现象 | 自检表 |
| C03-S2 三层剥法 | 机制 | 拆解模板 |
| C03-S3 抽章测试 | 代价 | 三种处置 |

role 字段在 outline 里显式记账，缺一不可。

## 证据：本章就是按三层写的

C03-S1 给假整齐现象，C03-S2 给切法，C03-S3 给检验与代价。读者跳着读也能各取一层。推断：外人盲测「哪一节在讲机制」应能指对（未做读者测试）。

## 代价：三层不是万能语法

叙事型案例、历史演进型章节强行三层会拧巴。这类章按主导职能标注 role，其余层以段落形式存在。规则管的是「三种职能齐备」，不是「三个小标题」。

## 误区：用「小结」冒充代价层

小结复述前文，不回答失效条件。代价层必须引入新的信息：边界、反例、取舍表。
