# 抽掉一章还断链吗

三层落到了节上，只保证单章是论述。章与章若扣不住，全书仍是合集。抽章测试就是假装删掉某一章，看后文会不会悬空。

## 现象：每章都合格，整本却像多篇特稿

分开评审每章都能过。连起来读，第三章并不需要第二章。作者自己也说不清阅读顺序，只说「都写到了」。读者面临的选择是全买或全不买，跳读不安全。

## 机制：递进靠接口，不靠主题接近

两章主题相关，不等于递进。递进要求：本章接住上一节留下的未解问题。在文件里，这表现为两样东西。

| 接口 | 字段 | 判据 |
| --- | --- | --- |
| 节尾钩子 | bridge | 上一节留下了什么，写得出即接口成立 |
| 章间依赖 | deps / requires | 后文需要的前文产物，写得出来 |

bridge 含反问或未解问题时，往往正是「上一层解释不够用」的转折点。整章若找不出这样的转折，多半在平铺（E-011）。

## 测试步骤

1. 从目录划掉一章，不看正文。
2. 列出后文所有依赖它的节（deps 或实质引用）。
3. 数依赖数，并判断断链句是否成立。

| 依赖数 | 判读 | 处置 |
| --- | --- | --- |
| 0 | 可能是并列插入 | 并入他章或前移成入门 |
| 1–2 | 正常递进 | 保留 |
| 多数后文章都指着它 | 核心章 | 前移，避免读者跳过 |

## 证据：用本章目录自测

划掉 C02，则 C03 的 bridge「上一章把承诺和边界定了下来」悬空，依赖为真。划掉 C01，C02-S1 的预判判据引用断了。推断：四章递进成立（未做读者测试）。

## 代价：测试合格仍可能读不动

抽章测试检查结构，不检查句子。结构对而句子烂，读者仍会放下。另一个代价是误判：一章看起来零依赖，可能因为后文引用没写进 deps。先补 deps 再判，不要急着删章。

## 误区：把「主题无关」当成「零依赖」

跨章复用术语、复用判据，也是依赖。只统计「需不需要它教新知识」会漏掉概念债。

## 收束

结构扣住了，句子还要能经受复核。下一章进入成书：作者在「已检查」三个字上最常骗过自己。
